## 2026-10-30 — Файлы: «Открыть с помощью…» (Claude)

  помощью…». Щелчок заменяет меню на месте списком программ, которые умеют открывать этот
  тип; выбор запускает программу с файлом. Раньше файл открывался только программой по
  умолчанию (свои программы Пёрышка или `xdg-open`).
- Новый модуль `files/src/openwith.rs`: тип файла по `mime/globs2` (вес, длина шаблона,
  флаг `cs`), а без совпадения — по первым 512 байтам (текст / двоичный); родители типа из
  `subclasses` (text/x-rust → text/plain) и синонимы из `aliases`. Программы — `.desktop` из
  XDG_DATA_DIRS (плюс Snap и Flatpak) с `MimeType=`; без `Terminal=true`, `Hidden=true`,
  отсутствующего `TryExec`. Порядок: `[Default Applications]` и `[Added Associations]` из
  mimeapps.list, затем точный тип раньше родительского, программы Пёрышка первыми, дальше
  по имени; `[Removed Associations]` учитываются. Коды `Exec=` (%f %F %u %U %i %c %k %%)
  раскрываются, без кода путь дописывается в конец.
- Базу читают только при первом «Открыть с помощью» (≈2 мс на этой машине), потом держат и
  перечитывают, лишь если изменилась папка applications или mimeapps.list — в простое
  работы нет. Длинное имя программы обрезается многоточием, список не выходит за окно.
- Проверено: тесты `programs_for_a_file_default_first_then_by_type`, `exec_field_codes`,
  `open_with_lists_programs_for_the_file_in_place_of_the_menu` (25 тестов Файлов прошли),
  `cargo build --release` всего workspace без предупреждений; на системной базе списки для

## 2026-10-29 — Пакет feather-de.deb (Claude)

- `packaging/build-deb.sh` собирает `dist/feather-de_<версия>_<арх>.deb` без root и fakeroot
  (`dpkg-deb --root-owner-group`). Файлы раскладывает `install.sh` с PREFIX=/usr; PAM-правило
  заменяется стеком Debian, личный пример greetd из репозитория не кладётся. Версия из
  Cargo.toml, а вне тега `v<версия>` — `+git<дата UTC>.<коммит>`, чтобы каждая сборка была
  новее и apt её обновлял. Зависимости от библиотек считает `dpkg-shlibdeps` (только ELF,
  `feather-session` — скрипт), к ним — программы, которые окружение вызывает (pkexec, polkitd,
  xdg-user-dirs…), остальное — Recommends. postinst/postrm обновляют базу ярлыков, PAM-файл —
  conffile, права нормализуются независимо от umask.
- Первый потребитель — образ Пёрышко OS (отдельный репозиторий feather-os).
- Проверено: пакет 14 МБ, `dpkg-deb --info`/`-c` — владелец root, права 755/644, все системные
  файлы (помощник установщика, политика polkit, сеанс, PAM) на месте.

## 2026-10-29 — Программы из Файлов больше не наследуют игнорируемый SIGCHLD (Claude)

- .deb, открытый из Файлов, показывал «Не найдена программа dpkg-deb». Файлы и Терминал ставили
  `SIGCHLD = SIG_IGN`, а игнорируемый сигнал переживает `exec`: каждая открытая ими программа
  получала его, и её `waitpid` падал с ECHILD (установщик, скрипты, GTK-программы, Firefox).
  Новый `feather_ui::process`: `reap_children()` подбирает детей обработчиком (он при `exec`
  сбрасывается, дети стартуют чисто) — им пользуются Файлы и Терминал; `default_child_signal()`
  в начале установщика, Просмотра, TextEdit, Заметок и Калькулятора снимает унаследованный
  `SIG_IGN`. Установщик пишет «не найдена программа», только если её действительно нет.
- Проверено: интеграционный тест `feather-ui/tests/process.rs` (с обработчиком дочерний процесс
  не видит игнорируемый SIGCHLD, `output()` после сброса работает), тесты Файлов 17, Терминала

## 2026-10-26 — Исправление сброса камеры по ПКМ в Lineage II / Wine XWayland (Gemini/agy)

- В `src/pointer_constraints.rs` и `src/input.rs` устранены три причины рывков и сброса камеры
  при вращении с зажатой ПКМ в Wine/GE-Proton (`L2.exe` / `winex11.so`) поверх `xwayland-satellite`
  и `Xwayland`:
  1. **Единый `wl_pointer.frame` для `relative_motion` и `motion`**: раньше `game_relative_motion`
     завершал отдельный `wl_pointer.frame` (`has_relative = true, has_absolute = false`), а следом
     `on_pointer_motion` отправлял второй кадр (`has_relative = false, has_absolute = true`). В
     `Xwayland` (`xwayland-input.c`) второй кадр с `has_relative == false` обходил
     `pointer_warp_emulator` и вызывал `dispatch_absolute_motion` без флага `POINTER_NORAW`, из-за
     чего Xorg синтезировал ложное событие `XI_RawMotion` на разницу между центром окна `(941, 510)`
     и старой абсолютной позицией курсора, а Wine (`broken_rawevents == 0`) передавал этот скачок
     прямо в игру.
  2. **Отказ от эхо-отправки `wl_pointer.motion` при снятии lock на XWayland и при отпускании
     кнопки**: `Xwayland` сам переставляет курсор Xorg перед вызовом
     `zwp_locked_pointer_v1.set_cursor_position_hint`; повторная отправка `wl_pointer.motion` без
     `relative_motion` при `destroy` или отпускании кнопки на той же XWayland-поверхности вызывала
     повторный абсолютный скачок после `XWarpPointer`.
  3. **Удержание `x11_warp_lock` пока зажата кнопка мыши**: в `L2.exe` (`windrv.dll` /
     `UWindowsViewport::SetMouseCapture`) при нажатии ПКМ вызываются `SetCursorPos(Center)` и
     `ClipCursor(&ClientRect)`. Wine захватывает `InputOnly`-окно `clip_window`, из-за чего через
     5 мс (`XFixesShowCursor`) `Xwayland` уничтожает `pointer_warp_emulator` (`LockedPointer`), не
     создавая `ConfinedPointer`, и блокирует последующие `pointer_warp_emulator` (`XYToWindow !=
     focus_window->toplevel`). Теперь при warp с зажатой кнопкой на XWayland-поверхности композитор
     сохраняет режим относительного захвата (`x11_warp_lock`) и точку нажатия (`SavedCursor`) до
     отпускания кнопки мыши.
- `cargo build --release` без предупреждений; 142 теста композитора и оба изолированных сценария
  `bench/game-check.py` (`--mode pointer`: 0 тиков CPU/5 с, пик `RssAnon` 36312 КиБ; `--mode x11` с
