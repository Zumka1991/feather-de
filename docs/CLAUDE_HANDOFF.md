## Как использовать Gemini 4 Argon

Личный skill уже существует:
`/home/zumka/.codex/skills/antigravity-subagent/SKILL.md` — прочитать и соблюдать.
Если Claude не загружает Codex skills автоматически, читать файл обычным инструментом.
Пользователь дал разрешение использовать внешнего агента в рамках проекта.

На этой машине executable `/home/zumka/.local/bin/agy`. `antigravity` — GUI IDE,
`gemini` — другой CLI. Проверять `command -v agy`, `agy --help`, `agy models`.
Подтверждённые варианты: gemini-4-argon-medium/high/low; по умолчанию medium.

Для ограниченного ревью:

```text
agy --model gemini-4-argon-medium --mode plan --output-format json \
    --print-timeout 180s --print "Конкретная задача с контекстом"
```

Передавать argv списком через Python subprocess, большой prompt сохранять во временный
файл и читать в Python; stdout JSON/stderr в разные файлы, внешний timeout 210 с.
Указывать точную задачу, файлы, ограничения, ожидать конкретные дефекты со строкой и
сценарием. Не менять те же файлы параллельно с агентом. Для текущего этапа успешно
получено два независимых анализа по тексту кода, без инструментов и изменений.

**Не использовать --dangerously-skip-permissions**, не менять авторизацию/настройки.
Ранее headless доступ к инструментам агента отклонялся: если снова denied_actions,
передать ограниченные релевантные фрагменты прямо в prompt и попросить анализировать
только текст без инструментов. `status: SUCCESS` с пустым response/планом/denied_actions
не является выполненным ревью. Изучить response и stderr, не повторять бесконечно.
--mode plan несовместим с --disable-slash-commands в проверенной CLI версии.

Подтверждённые замечания текущего Gemini исправлены; не исправлять автоматически
предположения из отчёта: например bounded output blocking на worker допустим и не
создаёт deadlock, пока calloop не ждёт worker. Ответ агента — материал для проверки,
не разрешение менять системные службы. Тесты и финальный diff проверяет основной агент.
