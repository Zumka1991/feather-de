# Верхняя панель и системные настройки — 2026-10-24

## Мышь и трекпад (2026-10-24, Claude)

Страница «Мышь и трекпад»: тема курсора (установленные темы с `cursors/` из XDG_DATA_HOME,
~/.icons, XDG_DATA_DIRS — сканирует воркер настроек), размер 24/32/48/64, скорость
(ползунок, libinput accel −1…1, шаг 0,1), естественная прокрутка отдельно для мыши
(по умолчанию выкл.) и трекпада (вкл.), касание вместо нажатия, основная кнопка справа.
Хранится в settings.conf (`cursor_theme`, `cursor_size`, `pointer_speed`, `natural_mouse`,
`natural_touchpad`, `tap_to_click`, `left_handed`). libinput-устройства DRM-сессии
запоминаются при подключении и перенастраиваются при каждом изменении; курсор композитора
перезагружает тему; новые программы получают XCURSOR_THEME/XCURSOR_SIZE. Во вложенном
режиме мышью управляет хост (страница об этом сообщает). На железе не проверено.

## Оформление Tahoe (2026-10-24, Claude)

Единая панель инструментов, плавающая боковая панель со светофором (`ManagedWindow::traffic_shift`),
сгруппированные формы. Разметка строится `Layout` в `controls()`, отрисовка и hit testing
используют одну геометрию; листы/меню — фиксированные элементы с подложкой `Scrim`.
Страница рисуется за 2,3–4,0 мс в 4K ×2. Фикстуры: `FEATHER_SETTINGS_FIXTURES=<dir>
cargo test --release --bin feather-de all_pages_paint`.

Перед изменениями сохранён весь предыдущий этап: коммит `327bcc0` на `master`.
Пользовательскую DRM-сессию не перезапускали. Подготовка выпуска отложена пользователем.

## Что работает

- Справа в меню-баре одинаковые интервалы и центры значков, подсветка наведения и
  открытого меню. Часы резервируют ширину: смена цифр не сдвигает соседние цели клика.
- Источник ввода обозначен компактным заполненным знаком `A`/`РУ`. Клик открывает
  список включённых источников, отметку текущего, сочетание клавиш и переход в
  настройки клавиатуры. Стрелки/Enter выбирают источник; смена языка не меняет ширину.
- «Системные настройки» доступны из меню Пёрышка и списка приложений. Четыре страницы:
  оформление, клавиатура, дисплеи, рабочий стол и Dock. Светлая/тёмная палитры,
  боковая навигация, прокрутка небольшого окна, единая геометрия рисования и кликов.
- Клавиатура: добавить/удалить/выбрать до четырёх источников из 12, последнюю раскладку
  удалить нельзя. Alt+Shift, Ctrl+Space или Ctrl+Shift. Применяется настоящая XKB-карта,
  меняются состояние клиента и индикатор, сохраняется выбранное сочетание и список.
- Оформление: светлая/тёмная тема, включение/отключение анимаций. Выключение завершает
  текущие переходы сразу, отключает прыжок запуска; повторное включение не переигрывает
  появление уже открытых окон. Рабочий стол: обои и увеличение Dock.
- Дисплеи: текущий вывод, разрешение и точная частота, масштаб 100–250 %. Масштаб,
  который оставит меньше 640×480 логических пикселей, отклоняется. Окна остаются достижимы.
- DRM: список режимов первого подключённого монитора, выбор разрешения/частоты,
  подтверждение и возврат через 15 секунд; при уходе на другой VT возврат ждёт
  активации сессии. Сохраняется только подтверждённый режим, привязанный к разъёму.
  Вложенный режим сообщает, что физический экран управляется внешней сессией.

**Физическое переключение KMS ещё не проверено:** по AGENTS.md это проверяет только
пользователь в DRM. Несколько мониторов, расположение экранов, hotplug и VRR остаются
следующим этапом бэкенда. Отображение списка режимов не означает их полную приёмку.

## Устройство и сохранение

`src/system_settings.rs` — модель, геометрия, UI и действия. `src/settings.rs` —
валидация настроек и worker сохранения/XKB. `src/shell.rs` — меню источников и меню-бар.
`src/animation.rs` — переключатель анимаций. `src/drm_backend.rs` — режимы KMS.

Файл `$XDG_CONFIG_HOME/feather-de/settings.conf` (обычно `~/.config/...`) совместим со
старой версией; новые поля: `animations`, `keyboard_layouts`, `keyboard_shortcut`,
`display`. Запись через временный файл и rename, последовательная, последний снимок
объединяет частые изменения. Диск и компиляция XKB includes — на `feather-prefs`,
готовая карта приходит в calloop. Переключение группы выполняется вне фильтра клавиш;
фокус по-прежнему меняется только через `refresh_focus()`.

Полный CPU-кадр настроек и его тень готовит `feather-raster`: owned-снимок, bounded
очередь, weak ticket, отбрасывание закрытого окна/устаревшего кадра. Результат содержит
только CPU-пиксели, не EGL/Wayland объекты. Главный поток сохраняет идентификатор
текстуры при неизменном размере, копирует готовые пиксели и ставит damage. При смене
размера забирает готовый буфер напрямую, без третьей полной CPU-копии. Во время
асинхронного ресайза предыдущий кадр масштабируется на GPU с явными `src`/`size`.
После установки кадра и submit освобождённые страницы возвращаются на worker;
периодического reclaim или таймера перерисовки нет.

## Повторение проверки

```sh
cargo build --release
dbus-run-session -- cargo test --workspace -- --include-ignored
FEATHER_PROFILE_UI=1 python3 bench/session-check.py settings --no-screenshot --output /tmp/feather-settings-budget
python3 bench/session-check.py settings --page input --output /tmp/feather-settings-input
python3 bench/session-check.py settings --dark --page displays --output /tmp/feather-settings-dark
python3 bench/session-check.py settings-restore --restore-from /tmp/feather-settings-budget --output /tmp/feather-settings-restore
```

Для полного сценария нужен новый каталог настроек, для restore — каталог предыдущей
приватной проверки. Runner создаёт свою D-Bus шину/конфигурацию/терминал, проверяет PID
перед изменением геометрии, не отправляет ввод хосту и завершает только свои процессы.
RssAnon считывается каждые 50 мс, CPU простоя — за последние 5 секунд.

Сценарий проверяет добавление DE, удаление RU, выбор источника мышью/меню и настоящим
Ctrl+Space, применённую XKB-группу, выключение анимаций при открытии окна, включение,
Dock, масштаб 125→200 %, содержимое файла и восстановление после перезапуска.
Unit-тесты также проверяют все 12×3 XKB-конфигурации, устойчивость разбора, геометрию
кликов на трёх масштабах в двух темах и равенство пикселей прямой/фоновой растеризации,
отбрасывание устаревшего кадра.

88 тестов workspace прошли, включая изолированные D-Bus тесты. Release без
предупреждений. Все страницы отрисованы тестом в двух темах на ×1/×1,25/×2;
светлое оформление/клавиатура и тёмные дисплеи/Dock просмотрены визуально.
Старые пики GL >1 мс, первых CPU-кадров других панелей >4 мс и debug GPU-readback
остаются открытыми; эта задача не закрывает полную приёмку 4K/DRM.

### Замеры вложенного 4K ×2

| Прогон | Пик RssAnon выборок, КиБ | RssAnon в конце, КиБ | Тиков CPU / 5 с |
|---|---:|---:|---:|
| Без снимка, FEATHER_PROFILE_UI=1 | 57 312 | 42 564 | 4 |
| Без снимка, повтор без UI-профиля | 56 716 | 52 664 | 1 |
| Дополнительный аудит потоков, до прямой передачи при ресайзе | 63 324 | 53 436 | 0 |
| Меню источников, со снимком | 137 324 | 72 516 | 0 |
| Тёмные дисплеи, со снимком | 126 748 | 61 940 | 0 |
| Восстановление настроек, со снимком | 111 704 | 46 896 | 0 |

Первые два пика без readback укладываются в 60 **десятичных** МБ (57 312 КиБ = 58,69 МБ),
но дополнительный прогон выявил короткий пик 64,84 МБ. После этого при смене размера
убрана лишняя полная копия: готовый буфер передаётся напрямую.
Выборка 50 мс не доказывает отсутствие более короткого пика. Прогоны простоя дают
разные результаты, поэтому требование строго 0 тиков во всех сценариях не закрыто.
У терминала во всех этих полных сценариях 0 тиков/5 с. После действий нет повторяющейся
растеризации настроек: worker settings/reclaim засыпает. В журнале остаются более
дорогие первые кадры других встроенных окон/масштаба и GL, см. прежние отчёты.

GPU-readback даёт известное превышение памяти, включая остаточное после снимка;
это измерено отдельно и не скрыто выборками без readback. Артефакты:
`/tmp/feather-prefs-budget-final`, `/tmp/feather-prefs-budget-repeat`,
`/tmp/feather-prefs-input-final`, `/tmp/feather-prefs-dark-final`,
`/tmp/feather-prefs-restore-final` (report.json, session.log, frame.png при снимке).
