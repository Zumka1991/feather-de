## Исходное состояние передачи Claude (история; исправления выше)

1. **Dock: несколько копий и группировка + подпрыгивание при запуске** (сборка чистая,
   тестов и визуальной проверки ещё нет):
   - `DockItem.windows` — число окон, под иконкой до 3 точек (src/shell.rs ensure_dock_rendered).
   - Меню иконки: список окон (✓ переднее, ◇ свёрнутое) → `DockMenuAction::Window(id)`,
     «Новое окно» → `launch_app_instance` (src/main.rs), средний клик по иконке — новая копия
     (src/input.rs). Повторный клик по активной программе: несколько окон — следующее окно
     вперёд, одно — свернуть.
   - `Bounce` (src/shell.rs): иконка прыгает GPU-элементом над Dock (src/render.rs рядом
     с dock_buffer), Dock-буфер перерисовывается только в начале/конце; останавливается после
     появления окна с id ≥ `first_new_window` (`advance_bounce` в src/main.rs), иначе ~5 с.
   - Нужно: снимок (FEATHER_DEBUG_SCREENSHOT) во время прыжка, проверить, что в простое после
     окончания needs_redraw не остаётся true (0 тиков/5 с: bench/raster-check.py), тест на
     `Bounce::offset`, записать в CHANGELOG. `advance_bounce` ставит needs_redraw = true всегда —
     **проверить**: при `bounce == None` он сразу return, это нормально.

2. **Баг от пользователя: терминал при ресайзе в Пёрышке «закрывается и открывается новый».**
   - `Term::resize` проверен фаззом (тест many_resizes…) — не падает.
   - В Hyprland ресайз через hyprctl (по PID своего процесса) — не падает.
   - Значит, связка с Пёрышком при интерактивном ресайзе CSD-окна (xdg_toplevel.resize от
     клиента, terminal/src/main.rs `press` → `window.resize`). Возможно, это не падение,
     а анимация появления окна в композиторе (src/animation.rs) срабатывает заново, или
     окно размапливается. Добавлен сценарий: `FEATHER_DEBUG_DND=resize` (src/main.rs) —
     жмёт правый край окна feather-terminal и тянет; запуск:
     `XDG_CONFIG_HOME=/tmp/x FEATHER_SCALE=2 FEATHER_DEBUG_DND=resize timeout 6 target/release/feather-de --windowed --autostart "RUST_BACKTRACE=1 exec $PWD/target/release/feather-terminal 2>/tmp/rz.log"`
     затем смотреть /tmp/rz.log (паника?) и жив ли процесс; плюс FEATHER_DEBUG_SCREENSHOT.
   - Первый прогон этого сценария: паники нет, stderr терминала пуст — вероятнее, окно в
     композиторе заново проигрывает анимацию появления или размапливается. Снять кадры
     (FEATHER_DEBUG_SCREENSHOT_MS ≈ 3400) и проверить, жив ли PID терминала после ресайза.
   - Проверить в композиторе обработку resize-запроса для CSD без SSD (resize_edges_at
     работает только с has_titlebar) и что configure во время ресайза не даёт 0×0.

## Как проверять без участия пользователя

- Вложенный запуск: `target/release/feather-de --windowed` (активный VT: /sys/class/tty/tty0/active;
  Hyprland — wayland-1, Пёрышко пользователя — wayland-2). Снимки: FEATHER_DEBUG_SCREENSHOT.
- Отладочные сценарии без ввода хоста: FEATHER_DEBUG_CAPTURE, FEATHER_DEBUG_DESKTOP,
  FEATHER_DEBUG_DND=(пусто|move|menu|resize) — только внутри своего вложенного композитора.
- Простой/память: `/proc/<pid>/stat` (тики), `voluntary_ctxt_switches`, RssAnon.
- После каждой задачи — запись сверху CHANGELOG.md.
