# Фоновая подготовка ассетов, 2026-10-23

Вынесена тяжёлая подготовка обоев, размытия, иконок и плиток Launchpad из цикла событий.
Это функциональный объём соответствующего пункта задания 3, а не подтверждение всех
бюджетов SPEC или исчезновения libinput lag в настоящей DRM-сессии.

После этого этапа уменьшена память шрифтов: актуальные результаты 4K —
[MEMORY_CHECKS.md](MEMORY_CHECKS.md). Числа ниже сохранены как сравнение именно переноса
растеризации; прежнее превышение RssAnon не описывает последний release.

## Что изменилось

- `raster.rs`: один CPU worker, 64 запроса, 2 результата в calloop. Главный поток не ждёт
  свободного места и не читает файлы иконок. Когда очередь заполнена, работа повторно
  запрашивается после продвижения worker, в том числе после отбрасывания старых заданий.
- На worker идут procedural wallpaper, frosted blur, поиск файлов темы, SVG/PNG,
  macify, процедурные иконки и полный буфер плитки Launchpad (иконка + подпись).
  Renderer/EGL/Wayland-объекты туда не передаются; MemoryRenderBuffer создаётся без
  текстур, импорт в GL выполняется только при отрисовке на главном потоке.
- У каждого запроса снимок темы/масштаба. Thread-local override не меняет глобальные
  настройки другого потока; после задания восстанавливается даже при unwind.
  Immutable таблицы FontSystem общие через Arc, mutable glyph cache отдельный.
- Смена внешнего вида, обоев, размера или масштаба инвалидирует epoch. Плитки дополнительно
  привязаны к ticket экземпляра/страницы Launchpad. Старая работа не затирает новые данные.
- Во время ожидания иконок показан дешёвый placeholder, затем готовые иконки. Кэш — до
  4 МиБ пикселей/128 ключей, buckets 64/192/320 px. При вытеснении остаётся готовый preview
  64 px; это предотвращает повторный decode на каждом repaint при переполнении кэша.
- Launchpad держит только видимую страницу. Старое idle-prefetch соседних страниц удалено:
  оно выполняло тяжёлую работу на том же потоке, несмотря на слово «idle».
- Закрытие Launchpad освобождает его плитки и фон. На GNU после кадра очистки worker
  однократно вызывает `malloc_trim(0)` для уже свободных страниц: в промежуточной версии
  новый поток удерживал лишнюю арену. Это не изменение параметров аллокатора и не таймер.
  Результат reclaim не вызывает ещё одну перерисовку. На других libc этот шаг пропускается.
- Асинхронно готовый фон не используется с выдуманным размером `src`: до его получения
  сцена сохраняет обычный фон, а после установки используется фактический размер буфера.

CPU-композиция панелей, текста, встроенных окон и загрузка готовых пикселей в GL остаются
на основном потоке. Поэтому перенос ассетов не означает автоматического выполнения
бюджетов ≤4 мс UI / ≤1 мс сцена+GL для каждого кадра.

## Воспроизведение

Перед изменениями можно сохранить release во временный файл, затем сравнить:

```sh
cp target/release/feather-de /tmp/feather-before
# после изменений:
cargo build --release
dbus-run-session -- cargo test -- --include-ignored
python3 bench/raster-check.py --before /tmp/feather-before --visual
```

Скрипт выбирает **только PID своего процесса**, найденный в `hyprctl clients -j`.
На Hyprland задаёт floating 1440×900 логических пикселей; на хосте ×2 это framebuffer
2880×1800. Использует `FEATHER_SCALE=2`, частные каталоги конфигурации, отдельные логи/JSON.
Ввод не эмулирует, рабочие сессии не останавливает. Завершает только свою process group.
На другом хосте размер окна задаётся хостом, поэтому сравнивать нужно одинаковую геометрию.

Сценарий без screenshot: минимизация/восстановление → меню → Control Center → Spotlight →
Launchpad → закрытие; затем простой. Пять секунд считаются по `/proc/PID/stat`, поля 14+15.
Отдельные визуальные запуски: Launchpad до/после, Control Center и стресс.
Readback/PNG не входят в замеры времени кадра и памяти основного сценария.

`FEATHER_DEBUG_RASTER_STRESS=1` выполняет 18 однократных смен обоев/масштаба/страниц/
поиска/экземпляра Launchpad с интервалом 60 мс, пока worker ещё готовит старые задания.
Завершает тёмными обоями TahoeNight, масштабом 1,5 и новым Launchpad. Это отладочные
операции над собственным состоянием, без кликов в хост и без сохранения настроек пользователя.

## Проверки и ограничения

14 тестов, включая очередь/повтор запроса, preview при вытеснении, независимые настройки
потоков, старые/закрытые tickets и прежние DBusMenu/анимации.

Release собран без предупреждений, все 14 тестов прошли. Снимки Launchpad до/после,
Control Center и стресс-сценария просмотрены: плитки и подписи на месте, итоговая тёмная
тема/масштаб корректны. В логах нет panic, BAD_SURFACE и ContextLost.

### Сравнение до/после

Оба бинарника во вложенном режиме, framebuffer 2880×1800, масштаб ×2, одинаковая
последовательность действий, без screenshot и параллельной сборки. «До» — сохранённый
release после глобального меню, до переноса растеризации; это не чистый HEAD репозитория.

Первый полный прогон шёл через Hyprland `wayland-1`, оказавшийся на **неактивном tty2**.
Поэтому его 24–25 кадров/с — fallback вложенного режима, не результат приёмки FPS.
Затем сравнение повторено через активное Пёрышко `wayland-2` на tty3, без изменения VT
и без перезапуска рабочей сессии (`HYPRLAND_INSTANCE_SIGNATURE=`).

| Метрика | До | После |
|---|---:|---:|
| Первый CPU-кадр Launchpad, неактивный Hyprland | 200,52 мс | 1,50 мс |
| RssAnon после закрытия Launchpad, тот же прогон | 76724 КиБ (74,93 МиБ) | 71668 КиБ (69,99 МиБ) |
| Простой, тот же прогон | 0 тиков / 5 с | 0 тиков / 5 с |
| Первый CPU-кадр Launchpad, активный хост | 154,21 мс | 4,99 мс |
| Последующие CPU-кадры Launchpad, активный хост | 0,017 мс | 0,016 мс |
| Сцена+GL Launchpad: среднее / пик, активный хост | 0,93 / 3,97 мс | 0,84 / 2,62 мс |
| Частота анимации Launchpad, активный хост | 61 кадр/с | 63 кадра/с |
| RssAnon после закрытия Launchpad, активный хост | 79428 КиБ (77,57 МиБ) | 72376 КиБ (70,68 МиБ) |
| Максимальный RssAnon среди секундных проб, активный хост | 79428 КиБ | 83676 КиБ |
| Простой, активный хост | 18 тиков / 5 с | 2 тика / 5 с |

В активном хосте частота всех переходов после изменений — около 60 Гц (59–63 в отчёте
профайлера). Рабочая сессия продолжала использоваться; причина поздних CPU-тиков отдельно
не установлена. **Строгий ноль в активном хосте не подтверждён**, хотя в изолированном от
ввода неактивном окне обе версии дали ноль. По секундным пробам виден и временный рост
памяти: перенос работы в поток не гарантирует уменьшения пика. Пробы не являются
непрерывным измерением максимума.

Подготовка одной плитки теперь занимает примерно 3–6 мс на worker, но основной поток
не ждёт весь набор; иконки появляются по готовности. Перенос уменьшил длинную остановку
Launchpad, **не закрыл бюджеты**: панели/текст в активном прогоне всё ещё дают первый
CPU-кадр до 32 мс, есть пики GL >1 мс, RssAnon >60 МБ, в том числе после освобождения
Launchpad. Нужны отдельная оптимизация оставшейся композиции/памяти и контрольные замеры
4K/DRM. Сам DRM и возврат с другого VT проверяет пользователь в своей сессии.

Артефакты текущего прогона (временные, не входят в репозиторий):
`/tmp/feather-raster-check/final/` — сравнение и четыре PNG,
`/tmp/feather-raster-check/active-final/` — повтор на активном хосте; логи и JSON с пробами.

Скрипт поддерживает классические dispatchers и Lua API Hyprland 0.55+; синтаксис проверен
по [официальному списку dispatchers](https://wiki.hypr.land/configuring/core/dispatchers/)
и [выбору окна по PID](https://wiki.hypr.land/configuring/selectors/).
