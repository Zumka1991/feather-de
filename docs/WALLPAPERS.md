# Обои Feather — 2026-10-24

На странице «Рабочий стол и Dock» системных настроек появилась галерея: «Рассвет»,
«Сияние», «Горное озеро». Это оригинальные изображения, сгенерированные встроенным
image_gen, по 1672×941; файлы и точные промпты — [assets/wallpapers](../assets/wallpapers/README.md).
Оригиналы включены в бинарник, отдельный каталог установки для них не требуется.

«Выбрать своё изображение…» открывает окно выбора наших «Файлов»
(`feather-files --file-picker`, фильтр «Изображения»), сторонний диалог больше не нужен.
Окно запускается на socket **данного** Feather, а не на сокете хоста.
Отмена диалога сохраняет прежний фон. Поддержаны PNG, JPEG, WebP, EXIF-ориентация JPEG,
прозрачность сводится на нейтральный фон. Режим заполнения — центральное кадрирование
с сохранением пропорций. Другие режимы размещения пока не добавлены.

Выбор сохраняется в `settings.conf`: `wallpaper_image=builtin:feather-dawn` или
`wallpaper_image=file:<hex локального пути>`. Hex сохраняет Unicode, пробелы, переводы
строк и не-UTF8 байты пути без инъекции строк конфигурации. Выбор градиента очищает
это поле; смена светлой/тёмной темы сохраняет выбранное изображение. При ошибке
загрузки остаются предыдущие обои и отображается сообщение; если прежний файл тоже
пропал, используется стандартный градиент без бесконечной повторной загрузки.

## Подготовка и память

`src/wallpaper.rs`: источники, галерея, диалог и декодер. `src/raster.rs` заказывает
подготовку вне цикла событий. Короткоживущий процесс того же бинарника
`--decode-wallpaper` не инициализирует Wayland/GL: декодирует и передаёт фиксированный
RGBA-буфер через pipe. Чтение, ожидание процесса и диалог происходят только на workers.
Ограничения: обычный локальный файл до 32 МБ, сторона до 16384, лимит аллокаций
декодера 192 МиБ, address space 768 МиБ и alarm 10 с. Это не постоянная служба.

Рабочая текстура не больше 1920×1080, при другом соотношении сторон меньше. Обои
загружаются в GL один раз при изменении; полный CPU-буфер после загрузки освобождается.
Поэтому увеличенный буфер фотографии не остаётся в приватной памяти композитора.
Для стекла Dock/CC/Launchpad хранится маленькая размытая копия тех же обоев.
Старые результаты отвергаются по raster epoch. В простое нет декодирования/опроса файла,
слежения за изменением файла или анимации обоев.

Память помощника временно добавляется к памяти композитора: её нельзя считать
нулевой или скрывать за бюджетом основного PID. Runner отдельно фиксирует максимумы
RssAnon помощника и их одновременную сумму с композитором, с выборкой 50 мс.

## Проверка

```sh
cargo build --release
dbus-run-session -- cargo test --workspace -- --include-ignored
python3 bench/session-check.py wallpaper --no-screenshot --output /tmp/feather-wallpaper-budget
python3 bench/session-check.py wallpaper --output /tmp/feather-wallpaper-visual
```

90 тестов workspace прошли: все три оригинала, PNG/JPEG/WebP, cover crop, alpha,
разбор путей, остальные функции DE. Вложенный сценарий выбирает каждое изображение
галереи, нажимает реальную кнопку выбора, получает путь через тот же picker worker,
загружает свой PNG с пробелом/Unicode в имени и проверяет сохранённый путь. Окно
«Файлов» в этом сценарии само выбирает заранее известный файл (`FEATHER_PICKER_TEST_FILE`):
ввод в чужие окна не отправляется. Затем проверяются ошибка отсутствующего файла
и сохранение предыдущего фона. Окно выбора снято отдельно во вложенной сессии; ручной клик пользователем ещё не проверен.

Пики debug-readback, сцена+GL >1 мс и первые CPU-кадры некоторых прежних панелей
по-прежнему требуют отдельной оптимизации, см. [SYSTEM_SETTINGS.md](SYSTEM_SETTINGS.md).
