# Свои сочетания клавиш и повтор ввода — 2026-10-24

«Системные настройки → Клавиатура → Сочетания действий» позволяет записать сочетание
для 16 действий: поиск, приложения, терминал, файлы, Пункт управления, закрытие,
завершение, сворачивание, разворачивание, скрытие программы/остальных, Mission Control,
переход между столами и перенос окна на соседний стол.

Нажать строку, затем сочетание с Ctrl, Alt или Super. Esc отменяет запись; Backspace
или Delete без модификаторов отключает действие. Отдельная строка возвращает все
стандартные сочетания. Подсказка при записи закреплена внизу страницы и остаётся
видна при прокрутке. Конфликт показывает имя занятого действия и сохраняет прежнее
назначение; можно сразу нажать другую комбинацию.

`Super+L`, переключатель окон, переключение языка, Print, переключение VT,
аварийный выход и служебные сочетания перезагрузки/масштаба сохраняются. Запись не
выполняет назначаемое действие. Буквенная клавиша определяется по латинскому символу
из XKB, поэтому работает и при русской раскладке. Совпадение модификаторов точное;
Caps Lock и Num Lock не входят в сочетание. У терминала по умолчанию остаётся
дополнительный Super+T; при его переназначении/отключении этот вариант убирается.

## Устройство

- `src/shortcuts.rs`: действия, стандартные сочетания, проверка конфликтов и
  зарезервированных комбинаций, разбор/сохранение ограниченного списка назначений.
  Строки `keybinding=action;modifiers;keysym` либо `keybinding=action;off` сохраняются
  существующим worker настроек. Старый файл без этих строк сохраняет прежние назначения.
  Ручной обмен двух назначений восстанавливается после чтения всего файла; конфликтующий
  файл возвращается к стандартным назначениям.
- `src/input.rs`: сопоставление в фильтре, затем прежний `KeyAction` выполняется после
  выхода из `KeyboardHandle::input`. Фокус по-прежнему меняется через `refresh_focus()`.
- `src/key_repeat.rs`: один таймер только на время удержания редактирующей клавиши.
  Задержка и частота берутся из уже существующих настроек автоповтора. Тики вызывают
  общий обработчик поля напрямую: без повторной передачи в XKB и без синтетических
  `wl_keyboard.key`. Программы Wayland по-прежнему повторяют ввод сами.

Повтор работает в поиске, Launchpad, поиске часового пояса, ручной дате/времени и
пароле Wi-Fi. Повторяются печатные символы, Backspace/Delete, стрелки курсора с Shift
и Ctrl; в поиске также стрелки выбора результата. Enter, Escape, горячие клавиши и
перелистывание пустого Launchpad не повторяются. PAM/polkit не затронуты.

Любое новое событие клавиатуры отменяет прежний таймер; подходящее нажатие создаёт
новый. Клик, смена фокуса, потеря фокуса окна хоста, переход страницы настроек,
смена раскладки/параметров повтора и блокировка также останавливают повтор. Перед
каждым тиком проверяется исходное поле и окно. Отпущенная клавиша не оставляет таймер
в простое. Тики учитываются как активность для idle-notify и энергосбережения.

Поздний ответ worker компиляции XKB сохраняет актуальные задержку и скорость, если
пользователь успел поменять их во время подготовки раскладок.

## Проверки

- `cargo build --release`: без предупреждений.
- `dbus-run-session -- cargo test --release --workspace -- --include-ignored`:
  **165 тестов прошли**, включая конфликты, системные комбинации, отключение,
  сохранение, обмен назначений и допустимые клавиши повтора.
- `bench/keyboard-check.py`: собственный вложенный композитор, отдельная D-Bus шина,
  временные настройки и `FEATHER_DEBUG_INPUT_ONLY=1`. Ввод направляется только в
  этот экземпляр. Реальные клики его обработчиков выбирают строки сочетаний.
  Проверены запись, конфликт, отмена, отключение, отсутствие старого сочетания,
  работа в русской раскладке, буквы, Shift+Left, Backspace, прекращение после отпускания,
  потери фокуса и клика, поля даты/пояса, Launchpad, восстановление после перезапуска.
- При задержке 400 мс и частоте 20/с: через 250 мс один символ; через 900 мс — 11,
  после отпускания число больше не меняется. Снимок страницы ×2 просмотрен:
  `/tmp/feather-keyboard-visual/check/frame.png`.

Повторить, предварительно проверив владельца сокета хоста:

```sh
ss -xlp | rg 'wayland-'
python3 bench/keyboard-check.py --host wayland-1 --scale 1 --no-screenshot --output /tmp/feather-keyboard-verified
python3 bench/keyboard-check.py --host wayland-1 --scale 2 --output /tmp/feather-keyboard-visual
```

`wayland-1` в этих прогонах принадлежал рабочему DRM-процессу 953; его не
перезапускали. Скрипт останавливает только собственную группу процессов.
