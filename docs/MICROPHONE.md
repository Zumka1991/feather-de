# Звук и микрофон — 2026-10-25

Продолжена незавершённая работа Claude: служебные команды были оставлены в
`controls.rs`, страницы настроек и проверки закончены Codex; Gemini 4 Argon через agy участвовал
в статическом ревью и подготовил исправления трёх подтверждённых замечаний.

## Поведение

«Системные настройки → Звук» показывает сначала микрофоны, затем устройства вывода.
Для каждой группы доступны выбор устройства по умолчанию, регулятор 0–100 % и mute.
Уровень записи означает усиление, а не измерение текущего сигнала. Страница сама
не открывает поток записи и не сохраняет звук. Звуки предупреждений и интерфейса —
отдельный оставшийся пункт Roadmap.

Регуляторы работают кликом и перетаскиванием, сохраняют соотношение каналов.
Локальное превью следует указателю; команды во время движения отправляются с шагом
не менее 2 %, отпускание отправляет окончательное значение. Порог сравнивается
с последней отправленной командой, а не с предыдущим событием указателя.
При смене устройства по умолчанию или его отключении текущий захват отменяется.
Изменение уровня не снимает mute. Выбор устройства переносит только потоки,
использовавшие прежнее устройство по умолчанию; прочие потоки остаются на своих местах.
Состояние и сохранение устройств/громкости принадлежат звуковому серверу.
Для прохода через 0 % worker сохраняет последнее ненулевое соотношение каналов
присутствующего устройства. После отключения, смены индекса/числа каналов или
перезапуска worker эти сведения не наследуются.

Monitor sources выходов не попадают в микрофоны: учитываются `monitor_source`,
`monitor_of_sink` и `device.class=monitor`. Пометка «разъём не подключён» использует
доступность активного порта; без него — всех известных портов. Пустой список портов
у USB/виртуального устройства не считается отсутствием подключения.

## Выполнение и обновления

Все `pactl`-команды, JSON и ожидания выполняются существующим audio worker.
Команды идут через ограниченную очередь, общий дедлайн снимка и команды — 3 с.
Страница получает готовый снимок; её CPU-кадр, как и прежде, готовит raster worker.
Обновления от `pactl subscribe` включают source/sink/server. При событиях sink и командах вывода/медиаклавишах используются последние известные
входы: лишние `list sources` / `get-default-source` не задерживают очередь громкости.
Source/server-события выставляют отдельный атомарный флаг до пробуждения worker;
заполненная очередь пробуждений не теряет изменение входа. Явные действия с
микрофоном, Refresh и ошибки команд всегда запрашивают полный снимок.
Нового периодического опроса или таймера перерисовки нет. Обновление снимка помечает открытое окно настроек
грязным, даже когда Пункт управления закрыт.

Входы и выходы читаются независимо: отсутствие выхода не мешает микрофону, ошибка
получения входов не обнуляет рабочие выходы. Ошибки видны на странице; для повторной
попытки есть «Обновить устройства», обновляющее только звук. Отказ команды показывается
в открытых настройках до следующего явного действия; фоновый снимок его не стирает. Вне страницы действует прежняя обработка ошибок оболочкой.

## Проверки

```sh
cargo build --release
dbus-run-session -- cargo test --release --workspace -- --include-ignored
FEATHER_SETTINGS_FIXTURES=/tmp/feather-microphone-fixtures cargo test --release \
  all_pages_paint_at_fractional_scale_and_clicks_use_the_painted_geometry
ss -xlp | rg 'wayland-'
python3 bench/audio-key-check.py --host wayland-1 --microphone --scale 2 --duration 35 --protocol-summary \
  --output /tmp/feather-microphone-quiet-budget
python3 bench/audio-key-check.py --host wayland-1 --microphone --scale 2 --screenshot --protocol-summary \
  --output /tmp/feather-microphone-complete-visual
python3 bench/audio-key-check.py --host wayland-1 --scale 2 \
  --output /tmp/feather-microphone-complete-media
```

Сценарий `--microphone` использует отдельную D-Bus-сессию, конфигурацию и подставной
`pactl`; настоящий Pulse-сервер недоступен этому экземпляру. Он проверяет команды
реального worker и клики/перетаскивание через обработчики своего вложенного окна:
выбор USB-входа, уровень, плавное перетаскивание с применением до отпускания, mute,
перенос только записи старого входа, сохранение ошибки команды при новом снимке, внешнюю смену
уровня/устройства, отключение, ошибку входов и восстановление. Source-события
приходят через подписку. Ввод в окна хоста не отправляется; останавливается только
собственная группа процессов. Регрессия медиаклавиш использует тот же транспорт.

Автотесты дополнительно проверяют разбор Pulse/PipeWire, недоступный активный порт,
исключение monitor sources, одни входы без выходов, частичный отказ службы и
геометрию ползунка, отсутствие запросов входов при обновлении выхода и сохранение баланса при проходе через ноль (включая
последовательные нулевые снимки и смену/исчезновение устройства). Фикстуры страницы — светлая/тёмная тема при ×1/1,25/2.

## Итог при завершении этапа звука

`cargo build --release` завершился без предупреждений. Полный workspace:
**178 тестов прошли**, включая явно разрешённые read-only проверки живых служб.
Статическое ревью agy и подготовленные им изменения проверены Codex; сборки,
модульные и вложенные тесты выполнялись Codex, а не agy.

| Микрофон, со снимком | 92,21 МиБ | 46,47 МиБ | 0 тиков / 5,039 с | 0 событий |
| Медиаклавиши, регрессия | 31,51 МиБ | 31,51 МиБ | 0 тиков / 5,043 с | 0 событий |

Пик со снимком уложился в дополнительный бюджет двух кадров RGBA; память вернулась
ниже 60 МБ за 0,102 с после пика. Финальный кадр просмотрен, как и фикстуры тем/масштабов.
Сценарий проверил 11 успешных звуковых команд; отказ mute был намеренно введён
подставной службой и не был скрыт следующим успешным снимком состояния.

Порог асинхронного теста перетаскивания увеличен с 400 до 1400 мс: фикстура запускает
отдельный Python-процесс на каждый `pactl` (около 27 мс), и очередь не успевала
в прежнее окно. Перед ожиданием отдельно проверяется отправка промежуточных команд,
после него — реальное изменение уровня ещё до отпускания кнопки.
Промежуточные прогоны с 4/6 событиями клавиатуры хоста в окне простоя
не используются для приёмки. Дополнительные запросы входов сначала задержали очередь
удерживаемых Fn; это исправлено кэшированием по событиям, финальная регрессия прошла.

Общие бюджеты сцены/GL и первых CPU-кадров настроек **не приняты**: худший
профилированный кадр без снимка 39,64 мс, со снимком 119,00 мс; CPU-кадры настроек
на worker также превышают 4 мс. Нулевой установившийся простой не подменяет эти
открытые пункты SPEC и Roadmap.

## Ручная проверка

Рабочая DRM-сессия не перезапускается автоматически. Новая страница появится после
следующего входа с обновлённым бинарником. В настоящей сессии остаётся выбрать
подключённый микрофон, проверить слышимую запись и mute в приложении записи,
подключение/отключение устройства и сохранение выбора после нового входа.
На момент проверки встроенные аналоговые входы машины сообщали отсутствие штекера.
Общая приёмка старых пиков сцены/GL, CPU и аппаратного DRM остаётся открытой в SPEC.
