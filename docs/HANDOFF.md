# Задания на продолжение (для ChatGPT / следующего агента)

Перед началом прочитай `AGENTS.md`, `docs/SPEC.md` (бюджеты, архитектура) и `CHANGELOG.md`
(что уже сделано и какие ошибки уже были). После каждой задачи допиши запись в
`CHANGELOG.md` сверху.

Задачи упорядочены по ценности. Делай по одной, каждую доводи до проверки.

## 1. Анимации (этап 2 дорожной карты)
- Общий механизм: пружина (spring, без фиксированных длительностей), состояние анимаций в
  `FeatherCompositor`, пока анимация идёт — `needs_redraw = true` каждый кадр; в простое 0 %.
- Появление окна: масштаб 0.92→1 и прозрачность 0→1 (`RescaleRenderElement` вокруг центра +
  `alpha` у элементов поверхностей и рамки).
- Сворачивание в Dock: окно сжимается и летит к иконке в Dock (координаты слота есть в
  `MacShell.dock_slots`). Обратное — при восстановлении.
- Плавное появление меню, Spotlight, Control Center, Launchpad (alpha + лёгкий масштаб).
- **Только GPU-трансформации**: никаких перерисовок CPU-буферов на кадрах анимации.
- Приёмка: анимации на частоте экрана, `FEATHER_PROFILE` показывает ≤ 1 мс на кадр,
  в простое 0 тиков CPU.

## 2. Глобальное меню (DBusMenu)
- Сейчас в меню-баре только свои меню (`shell.rs`, `menu_rows`). Нужно показать меню самих
  программ для тех, кто умеет: Qt/KDE и часть GTK.
- Протоколы: Wayland `org_kde_kwin_appmenu` (KDE-программы сообщают D-Bus сервис и путь меню
  своего окна) и D-Bus `com.canonical.dbusmenu` (`GetLayout`, `Event`, сигналы обновлений).
  Для GTK: `org.gtk.Menus` / `org.gtk.Actions` через `gtk_shell1` — второй приоритет.
- D-Bus только асинхронно (например, `zbus` в отдельном потоке + канал в calloop), цикл
  событий не блокировать.
- Electron/Firefox/Chrome это не поддерживают — для них остаются текущие меню.
- Приёмка: в Kate/Dolphin/Konsole в меню-баре видны их «Файл / Правка / Вид», пункты работают.

## 3. Мелкие ошибки, замеченные пользователем/при тестах
- Уведомление (toast) перекрывает верх Control Center — сдвигать toast или скрывать его,
  пока открыт Control Center (`shell.rs`, `toast_rect`, `cc_layout`).
- libinput в DRM-сессии иногда пишет «event processing lagging behind by ~25 ms» при старте
  и после возврата с другой консоли: тяжёлая CPU-растеризация в цикле (обои, плитки, иконки).
  Вынести растеризацию обоев/иконок в фоновый поток (результат — через канал в calloop).
- Отладочный скриншот во вложенном режиме даёт `ContextLost(EGLCreateSurface)` после снимка
  (`render.rs`, `save_screenshot`) — не влияет на работу, но стоит разобраться.

## 4. DRM-бэкенд, вторая версия (этап 4)
- Несколько мониторов и горячее подключение (udev `UdevEvent::Changed`), выбор режима и
  частоты, VRR.
- «Рендер впритык к vblank» (задержка ввода): начинать кадр за 2–3 мс до vblank, а не сразу
  после предыдущего. Мерить `FEATHER_PROFILE=1` («клавиша → кадр»).
- XWayland через `xwayland-satellite` (X11-программы в DRM-сессии сейчас не запускаются).
