# Файлы (feather-files)

Собственный файловый менеджер Пёрышка в стиле Finder macOS Tahoe. Отдельная программа —
Wayland-клиент в крейте `files/` того же workspace; `cargo build --release` собирает оба
бинарника, Dock запускает `target/release/feather-files` рядом с композитором (иначе Dolphin).

## Устройство

- `main.rs` — Wayland (smithay-client-toolkit 0.19): окно с собственной рамкой (CSD; углы
  и тень рисует Пёрышко), `wp_fractional_scale_v1` + `wp_viewporter` — буфер рисуется ровно
  в ×1,25/×1,5/×2 без пересэмплирования; wl_shm `Abgr8888` (композитор теперь его
  объявляет) — tiny-skia рисует прямо в разделяемую память, без копии и перестановки
  каналов. Курсоры через cursor-shape, буфер обмена файлов — `text/uri-list` в обе стороны.
- `app.rs` — модель и интерфейс без Wayland-типов: ввод → `Effect` наружу; тестируется
  без композитора и рендерится в PNG (`FEATHER_FILES_PREVIEW=/dir cargo test -p feather-files preview -- --ignored --nocapture`).
- `fsops.rs` — чтение каталога, копирование/перемещение, корзина freedesktop
  (`~/.local/share/Trash/{files,info}`) — в коротких потоках; inotify только на открытую папку.
- `feather_ui::file_icons` — процедурные папки (с гравировкой у пользовательских) и документы с бейджем
  типа; растеризуются один раз на размер и только копируются.
- Общий крейт `crates/feather-ui`: масштаб, текст, примитивы, иконки и типы файлов, корзина,
  XDG-папки и inotify — тот же код, что у композитора (значки рабочего стола выглядят так же).

## Возможности

Боковая панель (Избранное: Домой, Рабочий стол, Документы, Загрузки, Изображения, Музыка,
Видео, Корзина; Места: Компьютер, диски и флешки), назад/вперёд, значки/список,
поиск-фильтр, строка пути с переходом, контекстное меню, выделение рамкой, Ctrl/Shift-клик.

Диски в «Местах» берутся из sysfs, базы udev (`/run/udev/data`) и `/proc/self/mountinfo` — без
подпроцессов. Видны все разделы с файловой системой, кроме системных (смонтированных вне
`/media`, `/run/media`, `/mnt`), EFI, раздела восстановления Windows и помеченных
`UDISKS_IGNORE`. Неподключённый диск нарисован бледнее; клик подключает его через
`udisksctl mount` (пароль, если нужен, спрашивает polkit-агент Пёрышка) и открывает. У дисков,
подключённых udisks, справа кнопка ⏏: размонтирует, а флешку ещё и обесточивает. Список
обновляет фоновый поток, который спит в `poll` на inotify `/run/udev/data` и POLLPRI
`mountinfo`; окно на пропавшем диске уходит в Домой.

Клавиши: Enter/двойной клик — открыть (файлы через xdg-open), Backspace/Alt+↑ — вверх,
Alt+←/→, Ctrl+[ ] — история, стрелки/Home/End/PgUp/PgDn (+Shift), набор букв — переход,
Ctrl+F — поиск, F2 или медленный второй клик по имени — переименование,
Ctrl+Shift+N — новая папка, Ctrl+C/X/V — файлы, Delete — в Корзину, Ctrl+H — скрытые,
Ctrl+1/2 — вид, F5/Ctrl+R — обновить, Ctrl+W — закрыть.

Пробел — [быстрый просмотр](QUICK_LOOK.md) изображений и текста (стрелки переключают,
Escape/пробел закрывают). Ctrl+L/⇧Ctrl+G — ввод пути, в меню — «Свойства».
Поиск и переименование используют [общие поля](TEXT_INPUTS.md) с курсором и выделением.
[Тёмная тема](CLIENT_APPEARANCE.md) применяется и к уже открытым окнам.

Архивы, как в macOS: «Сжать» в меню делает zip, а двойной клик или «Распаковать» распаковывает
архив рядом с ним в фоне. zip, tar.*, 7z распаковывает bsdtar (libarchive-tools), RAR — unar
(пакет `unar`): libarchive на RAR5 зависает или сбивается. Многотомные `имя.partN.rar`
распаковываются с первого тома, на какой бы ни щёлкнули. Битый архив или нехватка тома дают
сообщение по-русски.

Распознаются tar.gz/xz/zst/bz2/lz/lzma (и короткие tgz, txz, tzst, tbz2, tlz), tar, zip, 7z, rar,
одиночные gz, xz, bz2, zst, lz, lzma, а также cab, arj, lzh/lha, cpio и ace. Если bsdtar архив не
прочитал (одиночный `.gz`, ARJ, ACE, deflate64…), распаковку повторяет unar; вопрос о пароле
остаётся за bsdtar, а если не справились оба, показывается ошибка bsdtar. Zip из Windows с
русскими именами без флага UTF-8 (CP866) распознаётся по центральному каталогу (читается только
конец файла) и распаковывается с `--options zip:hdrcharset=CP866`; zip с UTF-8-именами без флага
(старый Info-ZIP) не трогается.

«Файлы» — обработчик архивов в `.desktop` (`Exec=feather-files --open %F`, MIME-типы zip, 7z,
rar, tar.*, gz, xz, bz2, zstd, lzip, lzma, cab, arj, lha, cpio, ace): архив, открытый из Telegram,
с Рабочего стола или через xdg-open, сразу распаковывается рядом с собой. Без `--open` (как при
«Показать в папке» через FileManager1) файл только выделяется.

«Упорядочить» — по имени, типу, дате изменения или размеру, папки всегда сверху. Выбор — в
контекстном меню пустого места (раздел «Упорядочить» с галочкой) или кликом по заголовку
колонки в виде списка; повторный клик меняет направление (˄/˅ у заголовка). Даты и размеры
сначала идут от новых и больших, как в Finder. Порядок держится при перечитывании папки, пока
открыто окно; выделение и курсор при смене порядка сохраняются.

Архив с паролем открывает окно «Введите пароль для «…»» с полем из точек (общее поле ввода,
копирование и вырезание из него запрещены, вставка можно). «Распаковать» неактивна, пока поле
пустое. После Enter распаковка запускается заново в фоне: unar получает пароль через `-p`, bsdtar
(zip) — через `--passphrase`. Зашифрованный 7z libarchive не расшифровывает, поэтому его тоже
распаковывает unar. При неверном пароле окно появляется снова с красной строкой «Неверный пароль».
Пароль хранится в `Zeroizing<String>`, в журнал и Debug не попадает и стирается, как только поток
распаковки закончит работу. bsdtar запускается без управляющего терминала и с stdin только на
запись: иначе без пароля он спрашивает его в терминале или бесконечно читает пустой stdin.

## Режим выбора файла и портал (2026-10-24)

`feather-files --file-picker` читает JSON-запрос из stdin (`feather_ui::picker::Config`:
режим открыть/сохранить/папка, несколько файлов, фильтры glob/MIME, choices, стартовая
папка и имя), пишет выбор в stdout; пустой вывод — отмена. Сохранение спрашивает
подтверждение замены. Пути передаются байтами (Unicode/не-UTF8). Запрос ≤64 КБ,
ответ ≤2 МБ, ≤64 путей.

Им пользуются настройки обоев и backend XDG Desktop Portal `FileChooser`
(`feather-de --file-portal`, `src/file_portal.rs`): отдельный D-Bus-активируемый
процесс без Wayland/GL, OpenFile/SaveFile/SaveFiles, Request.Close только от владельца
(завершает окно через pidfd), не больше 4 диалогов одновременно. SaveFiles не
перезаписывает существующие файлы — добавляет « (N)». В DRM-сессии (`--standalone`)
пишутся пользовательские `feather.portal`, `featherde-portals.conf` (только если его ещё
нет, остальные порталы — gtk) и D-Bus service; глобальный `portals.conf` не меняется.
Приложениям выставляются `GTK_USE_PORTAL=1`, `PLASMA_INTEGRATION_USE_PORTAL=1`
и, если тема Qt не задана, `QT_QPA_PLATFORMTHEME=xdgdesktopportal`.

Ограничения: работает только для программ, которые спрашивают портал. Программы со
своим встроенным диалогом (часть Electron/Chromium без портала, старые GTK без
`GTK_USE_PORTAL`) продолжат показывать свой. Уже запущенный `xdg-desktop-portal`
подхватит backend только после перезапуска сессии.

Проверка: `python3 bench/session-check.py portal` — приватная шина, настоящий
`xdg-desktop-portal`, OpenFile с фильтром/choices, SaveFile без создания файла, Close.

## Замеры (2026-10-23)

Вложенное Пёрышко ×2: первый кадр через ~123–132 мс после запуска (в основном поиск
шрифтов через fc-match), простой 0 тиков/5 с, RssAnon 1,5 МБ (VmRSS 15,6 МБ, из них ~9 МБ —
общий буфер окна). Полная перерисовка 2000×1280 px ≈ 6 мс CPU; движение мыши над файлами
не перерисовывает ничего, только наведение на элементы с подсветкой.

## Ограничения / дальше

(при прокрутке — полный кадр). Полноценный PDF-просмотр ещё не добавлен. DnD и очистка
Корзины уже реализованы, см. [TRASH.md](TRASH.md).
