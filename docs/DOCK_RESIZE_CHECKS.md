# Dock и исчезновение терминала при ресайзе — 2026-10-23

## Причина исчезновения терминала

Воспроизведено настоящее падение клиента, а не повторное появление окна композитора.
`SlotPool::new_slot` в smithay-client-toolkit округляет память до 64 байт. Возвращённый
`create_buffer` canvas может быть длиннее `width * height * 4`. Терминал копировал
Pixmap в весь slot через `copy_from_slice`, который требует одинаковую длину срезов.

Точный случай из Wayland-лога: логический размер 733×219 при ×2, буфер 1466×438,
2 568 432 байта пикселей и 2 568 448 байт slot. Паника в terminal/src/main.rs;
далее клиент сам уничтожает xdg_toplevel и wl_surface, процесс завершается.
Ресайз ядра VT этого не проверял: ошибка находилась в передаче готового кадра Wayland.

Общий `feather_ui::draw::copy_shm_pixels` копирует и при необходимости меняет R/B только
в области пикселей, не затрагивая хвост выравнивания. Используется терминалом и DnD-иконкой
«Файлов»; основной canvas «Файлов» также ограничен размером пикселей. Регрессионный тест
проверяет точный аварийный размер, нечётные размеры, оба порядка каналов и сохранность padding.

## Dock

- После клика позиция значка закрепляется до ухода указателя из Dock. Добавление/удаление
  плитки свёрнутого окна не уводит значок под соседний при повторном клике.
- Контекстное меню отслеживает текущий slot значка: при исчезновении увеличения меню
  переносится вместе с ним, сохраняя отступ 10 логических пикселей. Меню рабочего стола
  сохраняет привязку к точке открытия. Перестановка меню не перезапускает его пружину.
- Прыжок начинается только если через 200 мс после запуска ещё нет нового mapped-окна
  данного приложения. Быстрый запуск не создаёт буфер анимации. При появлении окна прыжок
  заканчивается на ближайшем приземлении; пропущенный кадр не продлевает анимацию.
  Если окно не появилось, действует предел около 5 с.

## Повторение проверок

```sh
cargo build --release
dbus-run-session -- cargo test --workspace -- --include-ignored
python3 bench/dock-resize-check.py resize --output /tmp/feather-resize-check
python3 bench/dock-resize-check.py dock --output /tmp/feather-dock-check --screenshot-ms 8800
python3 bench/dock-resize-check.py slow --output /tmp/feather-slow-check --screenshot-ms 2900
```

Сценарии используют отдельные настройки и только собственный вложенный композитор.
Hyprland-окно выбирается строго по PID нового процесса; геометрия рассчитана на установленный
Hyprland 0.56 (Lua dispatch). Ввод хоста в тестовое окно отключён через
`FEATHER_DEBUG_INPUT_ONLY=1`: движения мыши пользователя не подменяют координаты сценария.
Остальные окна/сессии и их ввод не меняются; завершение — только собственная группа процессов.

`resize` тянет четыре края и четыре угла в обе стороны с отдельной отправкой движений,
проверяет один и тот же id, mapped/minimized и отсутствие повторной анимации появления;
затем запрашивает точный аварийный размер. Python проверяет живой PID клиента до конца.
`dock` проверяет четыре клика в одну точку, средний клик, «Новое окно», три окна в группе,
обход всех трёх окон и привязку меню после ухода указателя. `slow` добавляет перед запуском
тестового терминала задержку 800 мс и проверяет отложенный прыжок; обычный запуск — его отсутствие.

`report.json` содержит тики за последние 5 с, наблюдаемый RssAnon, VT и WAYLAND_DISPLAY.
Профиль без снимка нужен отдельно: ReadPixels снимка и смена VT искажают затраты кадра.
Вложенные проверки не заменяют приёмку DRM, FPS на неактивном VT не принимается.

## Результат проверки Codex

`cargo build --release` — без предупреждений. Все 72 теста workspace проходят
(39 композитора, 8 «Файлов», 20 терминала, 5 feather-ui).
Все перечисленные end-to-end проверки прошли; снимки трёх точек/списка окон и поднятой
иконки при медленном запуске просмотрены. В resize-логе только одно создание/маппинг
терминала, без уничтожения/повторного маппинга, PID жив до завершения теста.

Без скриншотов, вложенный 3840×2160, ×2, RX 580, WAYLAND_DISPLAY=wayland-1:

| Сценарий | Тики за последние 5 с | Пик RssAnon, КиБ | RssAnon в конце, КиБ |
|---|---:|---:|---:|
| Dock, быстрые запуски | 0 | 44 148 | 40 320 |
| Ресайз терминала | 0 | 38 844 | 38 844 |
| Dock, задержка 800 мс | 1 | 42 828 | 38 060 |
| Задержка 800 мс, повтор | 0 | 44 160 | 40 332 |

Максимальный наблюдаемый пик без readback — 45,2 МБ, ниже 60 МБ. После завершения
прыжка продолжающихся кадров нет; единичный тик первого медленного прогона сохранён
в отчёте, а не исключён из результатов. Односекундный housekeeping существовал до этих правок.

Артефакты текущего прогона: `/tmp/feather-handoff-check/{dock-profile,resize-verified,
slow-profile,slow-profile-repeat}`; снимки — `dock-verified/frame.png`, `slow-verified/frame.png`.
Исходная паника — `resize-12500-terminal.log` в той же корневой папке.

Ограничения приёмки: активен tty3 пользователя, хост Hyprland на tty2 неактивен;
частота анимаций в этих прогонах не является проверкой FPS. Сохраняются пики сцена+GL
выше 1 мс и первых CPU-кадров выше 4 мс: полная приёмка бюджетов CPU/GL остаётся открытой,
как и до этой задачи. Диагностический 4K readback отдельно даёт RssAnon 75 448–103 144 КиБ
(выше бюджета 60 МБ); эти пики не скрыты в измерениях обычной сцены и требуют отдельной
оптимизации захвата. Настоящая DRM-сессия пользователя не перезапускалась.
