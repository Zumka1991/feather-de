# Пёрышко (Feather DE) — спецификация

Документ задаёт цели, бюджеты, архитектуру и дорожную карту. Любое изменение должно
укладываться в бюджеты из раздела 2. Если не укладывается, это регрессия, даже если всё работает.

## 1. Цель

**Самое быстрое и лёгкое окружение рабочего стола под Linux с видом и поведением
последней macOS (Tahoe, Liquid Glass).** Светлая тема по умолчанию.

Принципы, в порядке приоритета:

1. **Отзывчивость.** Ввод и кадр клиента никогда не ждут композитор. Цикл событий
   не блокируется ни на чём (vsync, диск, D-Bus, запуск процессов).
2. **Ноль работы в простое.** Нет таймеров с частотой кадров и нет перерисовок «на всякий случай».
   В простое CPU равен 0 %.
3. **Память.** Буферы создаются по требованию и освобождаются, когда не нужны. Нет индексов
   «на всякий случай» (иконки ищутся точечно).
4. **Узнаваемость macOS.** Метрики, цвета, шрифты, поведение Dock/меню/Spotlight/Cmd+Tab.
   При конфликте с п. 1–3 выигрывает скорость, а внешний вид ищет другой способ.

## 2. Бюджеты (измеряются, а не предполагаются)

| Метрика | Бюджет | Исходный замер (RX 580, 4K, ×2) | Как мерить |
|---|---|---|---|
| CPU композитора в простое | 0 тиков за 5 с | 0 | `/proc/<pid>/stat`, поля 14+15 |
| Работа композитора на кадр (сцена + GL) | ≤ 1 мс | 0,65 мс | `FEATHER_PROFILE=1` |
| Блокировка на swap | ≤ 0,2 мс | 0,08 мс | `FEATHER_PROFILE=1` |
| FPS анимации Chromium | = частота экрана | 60/60 | `bench/anim.html` |
| Приватная память (RssAnon) | ≤ 60 МБ | ~48 МБ | `grep RssAnon /proc/<pid>/status` |
| Перерисовка UI оболочки (меню, Dock) | ≤ 4 мс CPU | — | `FEATHER_PROFILE=1`, «CPU-буферы» |
| Холодный старт до первого кадра | ≤ 300 мс | — | время до первого `[feather-profile]` |

Около 150 МБ RSS приходится на Mesa/LLVM. Это разделяемые библиотеки, общие для всех
GL-процессов, и в бюджет они не входят.

Значения исходного замера не подтверждают бюджеты текущей версии после всех изменений.
После фоновой растеризации, оптимизации шрифтов/CPU-панелей и подключения служб CC
в проверенном вложенном 4K ×2 на активном Hyprland: RssAnon после Launchpad 34,46 МиБ,
наблюдаемый пик 52,15 МиБ (54,69 МБ), простой 0 тиков/5 с, анимации ~60 Гц.
Текущий отчёт: [CONTROL_CENTER.md](CONTROL_CENTER.md). Предыдущие сравнения:
[UI_CHECKS.md](UI_CHECKS.md), этапы памяти/worker — [MEMORY_CHECKS.md](MEMORY_CHECKS.md),
[RASTER_CHECKS.md](RASTER_CHECKS.md). Перерисовка Dock с иконками в 4K: 16–28 → 3,1–3,5 мс
(иконки точного размера, UI_CHECKS). Пики GL >1 мс и первые CPU-кадры панелей >4 мс
на активном хосте сохраняются; приёмка настоящей DRM-сессии открыта.

## 3. Архитектура

```
calloop EventLoop (один поток)
├─ ListeningSocketSource      — новые клиенты
├─ Generic(Display)           — запросы клиентов, обрабатываются сразу
├─ WinitEventLoop             — ввод хоста; Redraw = «предыдущий кадр показан»
├─ Timer 1 с                  — часы, RSS, истечение уведомлений
├─ appmenu channel            — готовые снимки меню от D-Bus worker
├─ raster channel             — готовые CPU-буферы иконок/обоев/плиток от worker
└─ idle-callback              — pointer focus → render_if_needed → flush_clients
```

| Модуль | Ответственность |
|---|---|

| `handlers.rs` | Протоколы Wayland: xdg-shell (+попапы), decoration, activation, dmabuf v4, cursor-shape, selection |
| `input.rs` | Клавиатура (фильтр, хоткеи, Alt+Tab), указатель, drag/resize, грабы |
| `animation.rs` | Аналитические пружины окон и панелей; трансформации и alpha, остановка без таймера |
| `appmenu.rs` | KDE Wayland appmenu, асинхронный DBusMenu/Registrar в отдельном потоке, отмена старых RPC при смене фокуса |
| `tray.rs` | StatusNotifierWatcher/host, значки и DBusMenu трея; worker, bounded очереди, сигналы без опроса |
| `controls.rs`, `controls/network.rs` | Снимки и команды Wi-Fi NetworkManager/звука PipeWire Pulse compatibility, события на workers, bounded очереди |
| `control_panel.rs` | Страницы CC, пароль сети, локальное превью ползунка, реальные состояния и векторные иконки |
| `raster.rs` | CPU worker: ограниченные очереди, снимки масштаба/темы, отмена устаревших результатов; никаких EGL/Wayland объектов |
| `render.rs` | Сцена (front-to-back), damage tracking, темп кадров, frame callbacks, профайлер |
| `window.rs` | Модель окна: geometry, SSD/CSD, mapped, maximize/fullscreen, 9-slice тень, встроенные окна |
| `shell.rs` | UI оболочки: меню-бар, Dock, меню, Spotlight, Control Center, уведомления, переключатель |

| `cpu_profile.rs` | Опциональный FEATHER_PROFILE_UI: CPU-стадии и затраты примитивов/текста; без таймеров и вывода при выключенном флаге |
| `text.rs` | Шрифты (SF Pro → Inter → Noto через fontconfig), общий read-only mmap TTC, растеризация нужных глифов и ограниченный кэш масок |
| `icons.rs` | Файловый поиск/SVG/PNG на worker; ограниченный кэш готовых иконок в главном потоке, preview при вытеснении |
| `apps.rs` | Реестр приложений (.desktop), сопоставление окно → приложение, процедурные иконки |
| `settings.rs` | `~/.config/feather-de/settings.conf` |

### Конвейер кадра

1. Событие (ввод, коммит клиента, таймер) ставит `needs_redraw`.
2. `render_if_needed` ничего не делает, пока предыдущий кадр «в полёте» (`frame_pending`).
3. Грязные CPU-буферы перерисовываются, и в GPU загружаются **только изменённые области**.
4. `OutputDamageTracker` перерисовывает только изменённые области экрана, swap не блокирует (интервал 0).
5. Frame callbacks уходят клиентам сразу после submit: клиент рисует следующий кадр, пока наш показывается.
6. `WinitEvent::Redraw` (vblank хоста) снимает `frame_pending`. Страховка — 40 мс.
7. Кадр без damage не делает swap, а callbacks отправляются по таймеру 16 мс (защита от busy-loop).
8. Активная пружина оставляет `needs_redraw` до следующего vblank. После достижения цели
   пружина фиксируется точно в конечном состоянии; отдельного таймера анимаций нет.
   Свёрнутое окно рисуется до конца полёта, но сразу исключается из фокуса/ввода.
   Плитки видимой страницы Launchpad готовятся на worker; соседние страницы заранее
   не растеризуются, старые страницы освобождаются. Готовый результат вызывает damage,
   а не перезапуск пружины.

### Фоновая подготовка ассетов

Один `feather-raster` получает до 64 запросов, возвращает до 2 готовых результатов через
канал в calloop. Главный поток использует только `try_send`, worker спит на `recv`.
Обои, размытие, поиск/декодирование иконок (включая процедурные) и полные плитки Launchpad
готовятся вне цикла событий. Тема/масштаб фиксируются на время задания в thread-local
контексте; смена конфигурации меняет epoch, смена страницы/закрытие — ticket плиток.
Неподходящие результаты отбрасываются. Шрифтовые таблицы общие через Arc, кэши глифов свои.

Пиксельный кэш иконок ограничен 4 МиБ и 128 записями, при вытеснении остаётся готовое preview
64 px, не повторный decode. После закрытия Launchpad удаляются его буферы и фон; на GNU
worker однократно возвращает освобождённые страницы аллокатору после кадра очистки.
Настройки аллокатора не меняются, периодического trim/опроса нет. GL остаётся на главном
потоке. Сравнительные замеры и ограничения — [RASTER_CHECKS.md](RASTER_CHECKS.md).

Контуры всех символов заранее не разворачиваются: ttf-parser заимствует таблицы из
общего mmap, tiny-skia строит AA-маску только нужного глифа. Каждый поток хранит свои
маски, до 1 МиБ/4096 записей при обычных размерах UI. Файлы открываются только при старте.
fontdue остаётся исключительно эталоном метрик в dev-тестах. Проверка экономии, полного
RSS и внешнего вида — [MEMORY_CHECKS.md](MEMORY_CHECKS.md).

Панели используют ту же AA-геометрию, но сплошные цвета смешиваются целочисленным
premultiplied source-over, а билинейное стекло переиспользует две промежуточные строки.
Полноразмерного кэша обоев не добавлено. Обрезка текста линейная, kerning использует
кэшированные индексы глифов и нужную таблицу mmap без повторного разбора TTC.
Статическая основа Control Center готовится на raster worker после обоев: один ограниченный
буфер, только текущая тема/масштаб/геометрия. Уведомление скрыто, пока открыт CC.
Главный поток копирует основу и рисует живые подписи/регуляторы, при отсутствии основы
использует обычную растеризацию. Epoch/инвалидация общие с остальными ассетами.
Сравнение времени первого кадра и попиксельные проверки — [UI_CHECKS.md](UI_CHECKS.md).

### Правила, которые нельзя нарушать

- **Не блокировать цикл.** Запуск процессов идёт через `spawn`, файловый I/O допустим только при старте или по действию пользователя.
- **Не трогать фокус клавиатуры внутри `KeyboardHandle::input`** — будет дедлок. Нужно вернуть `KeyAction` и выполнить его после.
- **Фокус меняется только через `refresh_focus()`.** После изменения стека окон ставится `pointer_focus_dirty`.
- **Полноэкранные буферы** создаются лениво и освобождаются (см. оверлей). Damage от `render().draw` — только реальные области.
- **Растеризация на CPU** допустима лишь для того, что изменилось. Для анимаций нужны GPU-элементы и трансформации, а не перерисовка пикселей.
- **Новые протоколы** перед мержем проверяются под `WAYLAND_DEBUG=1` минимум с Chromium/Electron, Qt и GTK.

## 4. Протоколы

Есть: wl_compositor, wl_subcompositor, wl_shm, xdg_shell (toplevel + popup, move/resize/
maximize/fullscreen/minimize), xdg_decoration (решает клиент), xdg_activation_v1,
linux-dmabuf v4 с feedback, wl_data_device, primary_selection, wp_viewporter,
wp_fractional_scale_v1, wp_cursor_shape_v1, xdg_output.
Также `org_kde_kwin_appmenu_manager` v2: адрес меню связывается с конкретной wl_surface.
D-Bus worker отправляет снимки через ограниченный канал в calloop; главный поток
передаёт команды без ожиданий. Смена фокуса очищает меню сразу и отменяет старый RPC.

Очередь по ценности:

| Приоритет | Протокол | Зачем |
|---|---|---|
| P0 | `zwp_text_input_v3` + `zwp_input_method_v2` | IME, ввод в Chromium/GTK с `--enable-wayland-ime` |
| P0 | клавиатурный grab для `xdg_popup` | навигация по меню клавиатурой |
| P0 | `wp_presentation` | точный vsync-тайминг Chromium/Firefox/mpv |
| P0 | `zwlr_layer_shell_v1` | сторонние панели, уведомления (mako), лаунчеры |
| P1 | `ext_session_lock_v1`, `ext_idle_notify_v1`, `zwp_idle_inhibit_manager_v1` | блокировка экрана, гашение, видео без засыпания |
| P1 | `zwlr_screencopy_v1` / `ext_image_copy_capture` + xdg-desktop-portal | скриншоты, демонстрация экрана |
| P1 | XWayland (xwayland-satellite) | X11-приложения внутри DE, а не в labwc |
| P2 | `wp_linux_drm_syncobj_v1` (explicit sync) | NVIDIA, меньше задержек |
| P2 | `wp_content_type_v1`, `wp_tearing_control_v1` | игры, VRR |
| P2 | `wlr_data_control` | менеджеры буфера обмена |

## 5. Дорожная карта

Каждый пункт считается готовым, только когда выполнены критерии приёмки и не нарушены бюджеты из раздела 2.

### Этап 1 — «стекло» и скругления на GPU
- **Размытие под стеклом** (меню-бар, Dock, меню, Spotlight, CC, уведомления, Alt+Tab): dual-Kawase
  на GPU, пересчитывается только при damage под панелью.
  *Готово, если* на панелях виден размытый контент окон, а работа на кадр остаётся ≤ 1,5 мс.
- **Скругление углов клиентских окон** custom texture shader (как в niri); убирает
  квадратные нижние углы у SSD-окон. *Готово, если* углы совпадают с заголовком на любом масштабе.
- **Тени для CSD-окон без своей тени** — уже есть; проверить GTK4 и libadwaita.

### Этап 2 — анимации (macOS-физика)
- Пружинные анимации (spring, без длительностей): открытие/закрытие окна, сворачивание в Dock
  («genie» или «scale»), увеличение Dock, появление меню и Spotlight.
- Только GPU-трансформации (`RescaleRenderElement`, альфа). CPU-буферы не перерисовываются.
- *Готово, если* анимации идут на частоте экрана, простой — 0 % CPU, ввод не задерживается.

### Этап 3 — поведение macOS
- **Mission Control** (F3 / жест): все окна раскладкой, рабочие столы (Spaces) сверху.
- **Launchpad**: сетка приложений с поиском.
- **Cmd+` (Alt+`)**: переключение окон внутри приложения.
- **Глобальное меню**: Qt/KDE через Wayland appmenu + DBusMenu реализованы, GTK-native
  `org.gtk.Menus`/`org.gtk.Actions` остаётся. Поддержка определяется экспортом конкретного
  окна: установленный Chromium экспортирует DBusMenu, окна без экспорта сохраняют меню оболочки.
- **Центр уведомлений**: сервер `org.freedesktop.Notifications`, история, «Не беспокоить».
- **Control Center на реальных данных**: NetworkManager (Wi-Fi), BlueZ, PipeWire (звук),
  яркость (logind `SetBrightness`), батарея (UPower). Всё асинхронно, без блокировок цикла.
  Wi-Fi и звук реализованы, в том числе пароль Personal/SAE и выходы. Enterprise/hidden/WEP
  используют nm-connection-editor. BlueZ, яркость/батарея — следующие интеграции;
  текущие ограничения — [CONTROL_CENTER.md](CONTROL_CENTER.md).
- **Dock**: закрепление и открепление (контекстное меню), перетаскивание, отскок при запуске, индикатор
  внимания по `xdg_activation`.
- Горячие углы, Stage Manager (опционально).

### Этап 4 — собственный бэкенд DRM/KMS

**Первая версия есть** (`src/drm_backend.rs`, `src/cursor.rs`, `session/start-feather-drm.sh`):
libseat (logind) → udev (основная видеокарта) → GBM/EGL → `DrmOutputManager`, первый
подключённый монитор в предпочтительном режиме, кадры по vblank, libinput (тап и «естественная»
прокрутка на тачпаде), свой курсор из xcursor на аппаратной плоскости, Ctrl+Alt+F1…F12,
аварийный выход Ctrl+Alt+Backspace, пауза/возобновление при смене VT. Включается флагом
`--drm` или автоматически, если композитор запущен не внутри другого рабочего стола.
Лог: `~/.local/state/feather-de/drm.log`.

Ещё не сделано: несколько мониторов и горячее подключение, выбор режима/частоты, VRR,
explicit sync, XWayland (X11-программы в DRM-сессии не запустятся), рендер «впритык» к vblank.

Исходный план:
- Отказаться от labwc: udev + libseat + libinput + DRM/GBM, direct scanout полноэкранных окон,
  VRR, несколько мониторов, горячее подключение, explicit sync.
- *Готово, если* задержка ввод → фотон ниже, чем во вложенном режиме, а direct scanout
  работает для видео и игр. Это самый большой оставшийся выигрыш по задержке: сейчас каждый кадр
  проходит через второй композитор.

### Этап 5 — экосистема
- Приложение «Системные настройки» (тема, обои, Dock, клавиатура, дисплеи, горячие клавиши).
- Пользовательские обои (изображения), динамические обои день/ночь.
- Hot-reload конфигурации без перезапуска.

## 6. Тестирование и профилирование

- **Вложенный запуск:** `target/release/feather-de --windowed`. Из сессии самого
  Пёрышка тестовый экземпляр окажется вложен в него же и получит программный рендер.
  Для честных замеров запускайте его на хосте (`WAYLAND_DISPLAY=wayland-0` под labwc).
- **Профайлер:** `FEATHER_PROFILE=1` раз в 2 с печатает кадры/с, кадры с изменениями,
  коммиты клиентов, CPU-растеризацию, сцену+GL, худший кадр и время swap.
- **Визуальные тесты без эмуляции ввода:** `FEATHER_DEBUG_SCREENSHOT=/tmp/x.png` через 2,5 с
  сохраняет кадр самого композитора (а не экрана хоста — `grim` снимает то, что видно, и под
  тайловым WM легко сфотографировать чужое окно). `FEATHER_DEBUG_OPEN=launchpad` открывает
  Launchpad при старте.
- **Задержка ввода:** `FEATHER_PROFILE=1` печатает «клавиша → кадр» — от нажатия до отправки
  кадра с ответом приложения хосту (без задержки самого хоста и монитора).
- **Протокол:** `WAYLAND_DEBUG=1 <клиент>` — проверка фокуса (`wl_keyboard.enter`),
  режима декораций, configure.
- **Эталонный тест:** `chromium --ozone-platform=wayland --app=file://…/bench/anim.html`
  печатает FPS в консоль (`--enable-logging=stderr`). Должно быть = частоте экрана.
- **Регрессии, которые уже были и не должны вернуться:**
  - фокус на окне без буфера (невидимое окно перехватывает клики);
  - принудительный SSD поверх CSD («окно в окне»);
  - потерянное отпускание кнопки → клиент навсегда в implicit grab (мёртвые клики);
  - `xdg_toplevel.move` без `wl_pointer.leave` (мёртвые drag-области Electron);
  - блокирующий swap (браузер на ~35 FPS вместо 60);
  - dmabuf без feedback (Mesa-клиенты уходят в программный рендер);
  - в `under_from_surface_tree` передана относительная точка вместо глобальной: функция сама
    вычитает `location`, из-за чего попадание сдвигалось на координаты окна и верх/лево окон
    «не кликались». Проверка: `hyprctl dispatch movecursor` по краю окна, а в
    `WAYLAND_DEBUG` клиента `wl_pointer.enter` должен приходить с y ≈ 0;
  - курсор хоста 24 px на 4K: `XCURSOR_SIZE` задаётся в `start-feather-de.sh` по разрешению;
  - буфер низкого разрешения, растянутый на экран (`size` без `src` в
    `MemoryRenderBufferRenderElement`): Smithay берёт `src` = размер на экране и читает за
    пределами текстуры — обои показывали лишь угол с полосами.

## 7. Сессия и разработка

- Сессия: `session/feather-de.desktop` → `start-feather-de.sh` → labwc (kiosk) →
  `feather-session-inner.sh` → `feather-de --standalone` в цикле.
- `session/reload-binary.sh` пересобирает и перезапускает композитор. **Все окна закроются**,
  включая Claude Desktop, если вы работаете из этой же сессии.
- Настройки: `~/.config/feather-de/settings.conf` (appearance, wallpaper, scale, dock_zoom).
- Масштаб: `--scale 1.5` или `FEATHER_SCALE`, иначе автоматически по разрешению.
