# Закрепление, блокировка и порядок Dock — 2026-10-24

- ПКМ по приложению → «Закрепить в Dock» / «Открепить от Dock». Работающее
  незакреплённое приложение видно до закрытия последнего окна, включая свёрнутые окна.
  После открепления работающее приложение остаётся до выхода, закрытое исчезает сразу.
- Небольшое перетаскивание значка внутри секции работающих приложений больше не
  закрепляет его автоматически. Для закрепления перетаскиванием нужно перенести
  значок в секцию закреплённых; перенос из Launchpad также сохраняется.
- «Заблокировать Dock» есть в меню каждого значка, Корзины и фона панели. Галочка
  означает запрет перетаскивания в Dock, из Dock и перестановки значков. Клики,
  запуск, сворачивание и явное закрепление через меню остаются доступны. Заблокированный
  перенос не создаёт ghost/gap и не превращается в запуск при отпускании кнопки вдали.
- «Файлы» больше не добавляются в начало при каждом построении модели. Их место
  сохраняется наравне с другими значками; откреплять «Файлы» по-прежнему нельзя.
  В старую конфигурацию без «Файлов» значок добавляется один раз при загрузке, чтобы
  индексы вставки соответствовали видимому порядку. Перенос наружу не показывает
  ложное уведомление об удалении «Файлов».

Настройки: прежний `dock=<id,...>` сохраняет порядок, новый `dock_locked=true|false`
сохраняет блокировку (по умолчанию выключена). Запись идёт через существующий worker.
Старые закрепления пользователя и начальный набор приложений автоматически не удаляются.
Дополнительных таймеров, фонового опроса и пиксельных буферов нет.

## Повторение

```sh
cargo build --release
dbus-run-session -- cargo test --release --workspace -- --include-ignored
python3 bench/dock-resize-check.py pins --output /tmp/feather-dock-pins --scale 1
python3 bench/dock-resize-check.py dock --output /tmp/feather-dock-regression --scale 1
```

`pins` открывает два настоящих окна нашего терминала, проверяет последний close,
свёрнутые окна, настоящее ПКМ/выбор строк меню, случайное движение, оба направления
переноса, перестановку, блокировку, меню фона и Корзины, перенос «Файлов» в конец
закреплённой секции и сохранённый файл настроек. Все события поступают только в
отдельный вложенный композитор; настройки лежат в `/tmp`, завершение — по собственной
группе процессов. Ввод и рабочая DRM-сессия пользователя не меняются.

Для проверки повторного входа тот же `XDG_CONFIG_HOME` можно открыть с
`FEATHER_DEBUG_DOCK_RESTORE=1`: проверяются восстановленные блокировка и последнее
место «Файлов», затем открывается их контекстное меню. Прежний сценарий `dock`
проверяет клики/сворачивание, три окна, новое окно, Alt+Tab и привязку меню.

11 «Файлов», 3 «Заметок», 25 терминала, 8 feather-ui). Новые и прежний Dock-сценарии
прошли. Снимки галочки блокировки и позиции «Файлов» после повторного запуска просмотрены.
