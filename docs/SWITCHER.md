# Alt+Tab: редкий неверный выбор — 2026-10-25

Пользователь сообщил, что переключатель очень редко выбирает другое окно или
«сбивается». Точная исходная последовательность не записана. Gemini 4 Argon через
agy провёл статический анализ переданных фрагментов; Codex проверил выводы,
адаптировал патч, добавил защиту жизненного цикла выбора и проверки.
Первые 180 секунд CLI истекли без результата; завершённый анализ получен после
продолжения той же беседы. Это анализ кода, а не запуск тестов Gemini.

## Исправленные сценарии

- **Alt+Shift не ломает направление.** С настройкой `grp:alt_shift_toggle` XKB
  превращает второй модификатор в `ISO_Next_Group`: при Shift→Alt скрывается
  логический Alt, при Alt→Shift — Shift. Переключатель учитывает физически удерживаемые
  левый Alt и оба Shift дополнительно к логическим модификаторам. Состояние читается
  до keyboard filter, с учётом текущего события; блокировки внутри фильтра нет.
  Правый Alt остаётся логическим модификатором, чтобы не перехватывать AltGr.
  Смена раскладки продолжает работать; проверяются оба порядка и отпускание Shift
  до Alt, которое не должно преждевременно подтверждать выбор.

- **Текущая программа — начало списка.** Переход между Spaces менял фокус без
  перестановки глобального стека. Раньше элемент 0 мог относиться к другому столу,
  и первый Tab выбирал уже активную программу либо неожиданный элемент. Теперь
  фактически активная программа ставится первой; MRU остальных программ, включая
  другие столы, сохраняется. Не введён приоритет всех окон текущего стола перед MRU.
- **Выбор связан с живым окном.** Снимок списка хранит id представительного окна.
  При подтверждении через него заново разрешается актуальная группа программы.
  Закрытие первого окна неизвестной программы больше не ломает выбор оставшегося
  окна из-за изменения группирующего минимального id. Если выбранное окно исчезло,
  подтверждение отменяется и не запускает приложение заново. Индекс реестра
  приложений из старого снимка тоже не используется для запуска.
- **Мышь выбирает окно только по явному клику (обновлено 2026-10-27).** Движение и
  наведение указателя (`on_pointer_motion`) над видимой панелью `Alt+Tab` больше никогда
  не меняют `sw.selected`: при отпускании `Alt` всегда активируется программа, выбранная
  клавиатурой (`Tab` / `Shift+Tab` / стрелками). Если пользователь хочет вручную выбрать
  иконку мышью, он кликает по ней левой кнопкой мыши (`on_pointer_button`), что сразу
  подтверждает выбор. Геометрия hit testing вычисляется по актуальному списку до первого
  CPU-кадра и совпадает с отрисовкой.
- **Каждое открытие владеет своей задержкой.** Одноразовый таймер показа 45 мс
  проверяет время открытия своей сессии. Таймеры быстрых завершённых Alt+Tab больше
  не показывают следующую панель раньше срока. Постоянного таймера нет.
- **Отмена действительно закрывает панель.** Escape и потеря фокуса хоста
  помечают кадр и указатель для обновления. `release_all_input` отменяет переключатель
  до сброса клавиш; следующая посторонняя клавиша не подтверждает старый выбор.
- **Перехваченные клавиши отпускаются корректно.** Физические keycodes навигации
  сохраняются до их release даже после закрытия панели. Например, когда Alt отпущен
  раньше Tab, новый клиент не получает одиночный Tab release. То же относится к
  Escape/Enter и сбросу ввода при потере фокуса.
- **Свёрнутое окно с другого стола становится видимым.** Если у выбранной программы
  свёрнуты все окна, последнее восстанавливается на текущем столе, как при восстановлении
  из Dock. Раньше флаг `off_space` мог оставить восстановленное окно скрытым.

Семантика сохранена: Alt/Super+Tab переключает **программы**, Alt+` — окна активной
программы. Список во время удержания является снимком; индексы не пересортировываются
под пользователем. Закрывшийся выбранный экземпляр безопасно отменяет подтверждение.
Все изменения фокуса по-прежнему происходят после keyboard filter через deferred action
и `refresh_focus()`. Нового I/O в обработчиках, опроса или постоянных кадровых таймеров нет.

## Проверки

```sh
cargo build --release
dbus-run-session -- cargo test --release --workspace -- --include-ignored
ss -xlp | rg 'wayland-'
python3 bench/switcher-check.py --host wayland-1 --scale 2 --output /tmp/feather-switcher-budget
python3 bench/switcher-check.py --host wayland-1 --scale 2 --screenshot --output /tmp/feather-switcher-visual
```

`bench/switcher-check.py` создаёт собственный вложенный композитор с приватной D-Bus,
конфигурацией, данными и подставным `pactl`. Реальные звук/системные службы недоступны.
Фикстуры — mapped встроенные окна с разными app id, столами и состояниями. События
Alt/Shift/Tab/Escape проходят настоящие обработчики клавиатуры. Это проверка модели
выбора/активации и рендера, а не доставка клавиш внешнему Wayland-клиенту.

Проверяются MRU с окном другого стола наверху общего стека, вперёд/назад с обоими порядками Alt/Shift, 32 быстрых
чередования, release Alt раньше Tab, отмена и принадлежность таймера, закрытие первого
окна неизвестной группы, полностью закрытый выбор без повторного запуска, потеря
фокуса/посторонняя клавиша, восстановление свёрнутого окна с другого стола.

Модульные проверки дополнительно проверяют подавление дрожания и разрешение намеренного
наведения, актуальную геометрию до первого рендера и полноразмерный непустой CPU-буфер
первого кадра переключателя. Открытие не перезаписывает размер, по которому решается,
нужно ли выделять буфер: это отдельно проверено при адаптации предложенного патча.

## Результаты

Все **180 тестов** workspace прошли, включая разрешённые read-only проверки служб;
`cargo build --release` завершился без предупреждений. Первый вложенный прогон
воспроизвёл конфликт Shift→Alt с `grp:alt_shift_toggle`; после исправления прошли
все восемь групп сценариев, включая оба порядка модификаторов.

Финальные отдельные прогоны ×2, 2880×1800:

| Сценарий | Пик RssAnon | После сценария | Простой CPU | Ввод хоста в окне простоя |
|---|---:|---:|---:|---:|
| Alt+Tab, без снимка | 41,20 МиБ | 41,20 МиБ | 0 тиков / 5,039 с | 0 |
| Alt+Tab, со снимком | 87,33 МиБ | 47,77 МиБ | 0 тиков / 5,032 с | 0 |

Пик снимка укладывается в дополнительный бюджет двух кадров RGBA; возврат ниже
60 МБ занял 0,100 с после пика. Кадр просмотрен: три иконки, выделение и подпись
выбранной программы видны, панель целиком отрисована.
Дополнительно прошла `bench/dock-resize-check.py dock` с настоящими окнами
`feather-terminal`: циклическое переключение трёх окон, правильный фокус и выбор
иконки Alt+Tab кликом. Запускался собственный вложенный процесс с приватной D-Bus,
конфигурацией/данными и недоступными реальными звуковой/системной службами;
команды изменения геометрии хоста не вызывались. Пик по секундным сэмплам
38,89 МиБ, 0 тиков/5 с; этот старый сценарий не считает события ввода хоста,
поэтому для чистой приёмки простоя используются два протокольных прогона выше.
Отчёт: `/tmp/feather-switcher-client-regression`.
Регрессия медиаклавиш после изменений keyboard filter также прошла: 19 команд
подставному серверу, пик 31,62 МиБ, 0 тиков/5,044 с и 0 событий ввода хоста.
Отчёт: `/tmp/feather-switcher-media-regression`.


Логи/сэмплы: `/tmp/feather-switcher-altshift-budget` и
`/tmp/feather-switcher-altshift-visual`. Прежняя приёмка пиков кадра остаётся открытой:
худший профилированный кадр здесь 31,32 мс без снимка и 141,57 мс со снимком.

Рабочая DRM-сессия пользователя не перезапускалась. Исправления применятся после
следующего входа с новым бинарником. Повторение именно исходного редкого сбоя ещё
нужно проверить пользователю; перечисленные ошибки воспроизводятся отдельными сценариями.
Общая приёмка прежних пиков сцены/GL и CPU по SPEC остаётся открытой.
