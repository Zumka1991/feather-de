# Пункт управления — системные службы, 2026-10-23

## Что реализовано

- Wi-Fi через системный D-Bus NetworkManager: наличие адаптера, radio/hardware block,
  подключённый SSID/подключение, список AP, явное обновление/сканирование, включение/выключение,
  отключение активной сети, ActivateConnection для сохранённого профиля, AddAndActivateConnection
  для новой открытой/OWE/WPA-Personal/SAE сети. Смешанные WPA2/WPA3 сети распознают оба
  вида сохранённых профилей. SSID передаётся как байты, не через shell/CLI.
- Новые WPA-Personal/SAE сети запрашивают пароль в панели. Проверка длины до отправки,
  Enter/кнопка подключают, Esc возвращает список. Секрет Zeroizing, Debug команды скрывает
  данные; пароль не попадает в argv/логи/настройки Feather. NetworkManager сохраняет
  профиль своим стандартным способом. Ввод перехвачен, клиент теряет keyboard focus
  через refresh_focus() вне keyboard filter; фокус возвращается после формы.
- Для Enterprise, WEP, скрытых сетей и расширенных параметров — «Настройки сети…»
  (`nm-connection-editor`). Собственного универсального SecretAgent/802.1X UI пока нет.
- Звук через `pactl` и Pulse-совместимый сервер PipeWire: настоящие выходы, громкость/mute,
  выбор выхода. Уже играющие потоки старого default переводятся на выбранный выход,
  потоки на других выходах не трогаются. Канальный баланс сохраняется; шкала 0–100%
  показывает максимум каналов, без усиления выше 100%. Движение ползунка — локальное
  превью; системная команда одна при отпускании левой кнопки. Нажатие на значок динамика
  переключает mute, заголовок карточки открывает выходы.
- Векторные иконки всех карточек не зависят от наличия символов в шрифте. Уведомление
  скрывается при открытом CC. В результате достаточно одной фоновой основы CC вместо двух.
- Bluetooth открывает установленный `blueman-manager` (состояние/питание BlueZ прямо
  в панели ещё не реализованы). Яркость честно помечена недоступной; прежнего фиктивного
  изменения уровня больше нет. Тема, масштаб, обои и раскладка сохраняют реальные действия.
  «Не беспокоить» пока локальный флаг оболочки: сервер уведомлений — отдельная задача.

## Потоки и зависимости

`controls.rs`: bounded команды по 16 для network/audio, результаты через calloop по 4.
Главный поток только try_send, установки снимков и dirty при изменениях. Заполненная
очередь даёт понятную ошибку; главный поток не ждёт worker. Открытие панели обновляет
службы по одному разу, успешная отправка отслеживается отдельно для каждой службы.

`controls/network.rs`: отдельный zbus async worker. Подписка до снимка, PropertiesChanged
(включая invalidated), устройства и NameOwnerChanged. AP Strength/список собираются только
для открытой страницы Wi-Fi; в фоне читается активная AP. Очередь сигналов схлопывается,
старые AP/профили перепроверяются перед командой. Детальный режим сохраняется при
переподключении шины. После отказа самой системной шины повтор — при открытии панели,
без idle retry timer. D-Bus RPC ограничен 3 с; главный поток не блокируется.

`controls.rs` audio: один worker и один блокирующий event reader `pactl subscribe`.
Только sink/server события, coalescing wake по 1, snapshot сравнивается до публикации.
Запросы JSON ограничены 1 МиБ и 3 с, stdout nonblocking; shell не используется. Вся
команда переключения выхода имеет общий 3-секундный deadline; исчезнувший поток не
превращает успешную смену default в ложную ошибку. Subscription имеет cancellation FD
и PR_SET_PDEATHSIG, завершается вместе со своим процессом/worker. Периодического опроса нет.
Если сервер звука перезапустился и subscription завершился, новое открытие панели
повторно подписывается. Минимальные runtime зависимости: NetworkManager, `pactl` (libpulse),
Pulse-совместимый сервер (`pipewire-pulse` здесь), для расширенных сетей nm-connection-editor.

CLI выбран для ограниченного набора операций и отсутствия ещё одного native mainloop.
Если появится непрерывное применение громкости во время drag, сначала заменить/замерить
этот транспорт (например libpulse), а не запускать pactl на каждое движение.

## Проверка

`dbus-run-session -- cargo test -- --include-ignored`: 31 passed. Сюда входят отдельная
тестовая NM-служба с настоящими D-Bus типами, stale AP, saved/new connections, радио;
fake audio transport (имена отдельными аргументами, баланс, mute, перенос только нужных
потоков); валидация формы, редактирование без утечки Debug, одна команда slider release,
доступность последнего выхода при прокрутке, AA основы с динамическим регулятором.
Включены два explicit ignored probes: read-only чтение настоящих служб и снимки fixtures.
Тесты не меняют реальные подключения, громкость, mute и устройства пользователя.

На этом компьютере реальный NM видит Ethernet, Wi-Fi-адаптер отсутствует. Read-only
probe NetworkManager и PipeWire прошёл; подключение/пароль/radio проверены mock-службой,
не физическим Wi-Fi. Реальная запись звука проверяется пользователем вручную; fake
transport проверяет команды, не подтверждает слышимый результат на железе.

Снимки fixtures просмотрены: `/tmp/feather-controls/fixture-{wifi,sound,password}.png`.
Также просмотрены кадры самого nested композитора 2880×1800: общий CC, реальные Wi-Fi
и звук (`screenshots/cc{,-wifi,-sound}.png`). Иконки/регуляторы видны, toast панель не закрывает.
Снимок реальных страниц без эмуляции ввода:

```sh
FEATHER_DEBUG_OPEN=cc-sound FEATHER_DEBUG_SCREENSHOT=/tmp/cc-sound.png \
  XDG_CONFIG_HOME=/tmp/feather-cc-config timeout 6 target/release/feather-de --windowed
# Также: cc, cc-wifi. По имени feather-de процессы не останавливать.
```

Сравнение release до/после CC: активный Hyprland (tty2 в начале/конце обоих прогонов),
собственное окно 1920×1080 logical = 3840×2160 physical, ×2, без readback и UI tracing,
RSS sampler 100 мс. Анимации 60–63/с. RssAnon после закрытия Launchpad 37100→35288 КиБ
(36,23→34,46 МиБ), наблюдаемый пик 55812→53404 КиБ (54,50→52,15 МиБ = 54,69 МБ после).
Простой 1→0 тиков/5 с. Первый CPU-кадр CC 3,95→2,73 мс, последующие ~0,012 мс;
меню 10,86→2,40 мс. Это конкретные наблюдения на интерактивном хосте, не обещание
верхней границы; прежние замеры CPU >4 мс/пики GL >1 мс и приёмка DRM остаются открытыми.
Файлы: `/tmp/feather-controls/profile-4k/{before,after}.{log,json}`. После этого поправлены
только подпись отсутствующего адаптера и контур иконки луны; передача содержит новую сборку.

`review-report.json`. Полная дальнейшая передача — [CLAUDE_HANDOFF.md](CLAUDE_HANDOFF.md).
