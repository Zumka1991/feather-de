# Трей (2026-10-24)

В правой части верхней панели отображаются StatusNotifierItem: компактные значки 18 pt
с шагом 26 pt. Цвет и узнаваемость значка приложения сохраняются, символические значки
используются, если их предоставляет программа. При нехватке места появляется «+N» со
списком приложений; выбор открывает их меню. Это функциональный трей, а не список процессов.

Левая кнопка — Activate (или меню при ItemIsMenu), средняя — SecondaryActivate,
правая — меню, колесо — Scroll. DBusMenu рисуется оболочкой: каскады, галочки,
недоступные пункты, длинные списки, навигация стрелками/Enter/Esc. Уведомление не
закрывает открытое меню трея. NeedsAttention отмечается точкой без постоянной анимации.

## Устройство

`src/tray.rs`: org.kde.StatusNotifierWatcher + встроенный host, до 64 элементов.
Существующий watcher не вытесняется; при его выходе Feather пробует занять имя и
обслуживать новые регистрации. Обычная вложенная сессия не подключает этот host,
чтобы не менять трей рабочей сессии пользователя. DRM/standalone включает его сам.

Весь D-Bus, поиск IconThemePath и преобразование сетевого ARGB выполняет отдельный worker.
В calloop приходят снимки через ограниченный канал, команды отправляются через try_send.
GetAll и сигналы вместо периодического опроса; растеризация IconName — существующим worker
иконок. Pixmap проверяется по размерам/длине, приводится к premultiplied RGBA 40×40.
Смена/закрытие меню меняет поколение, поздние ответы не открывают его повторно.
Клик проверяется по текущему дереву: hidden/disabled/submenu не исполняются как действия.
Для Activate/Secondary передаётся ProvideXdgActivationToken; неиспользованный токен
удаляется через 10 с.

KDE регистрирует объект отдельного D-Bus соединения через общее соединение приложения.
При несовпадении unique names проверяется равенство GetConnectionUnixProcessID; это
поддерживает реальный KDE-клиент и не принимает регистрацию за чужой процесс.
Снятие произвольного well-known имени не удаляет остальные значки живого владельца.

## Исправление зависания, 2026-10-26

При сообщении об исчезновении всего трея в рабочей сессии watcher продолжал
содержать три регистрации, и все три приложения возвращали `Status=Active`.
В отдельном тесте воспроизведено зависание worker: во время `GetAll` приходят
160 событий `NameOwnerChanged`, переполняют очередь из 64 сообщений и блокируют
socket reader zbus. На том же соединении worker ждёт ответ/установку match rule,
поэтому вернуться к чтению событий уже не может. Таймаута RPC недостаточно для
ожидания внутренних блокировок zbus. Перезапуск приложений этого не исправляет.

Сигналы теперь принимаются отдельным D-Bus соединением; watcher, RPC и действия
остаются на прежнем. Очереди ограничены прежними размерами. При временном сбое
повторного `GetAll` сохраняется последний успешный снимок того же владельца;
`Passive` и снятие регистрации по-прежнему убирают значок. Опроса и новых таймеров нет.
Тест проверяет получение обновлённого заголовка после всплеска и следующую загрузку,
чтобы старый снимок не мог скрыть зависание.

Проверено: `cargo build --release` без предупреждений, 140 тестов композитора
на отдельной шине (`dbus-run-session -- cargo test -p feather-de -- --include-ignored --test-threads=1`).
Два настоящих Qt-значка, меню/действие, скрытие и возврат прошли `bench/session-check.py tray`;
собственный кадр 2880×1800 ×2 просмотрен. Отдельные прогоны без screenshot/readback,
`FEATHER_PROFILE=1`, на активном хосте Пёрышко:

| Метрика | Прежний бинарник рабочей сессии | Исправленная сборка |
|---|---:|---:|
| Простой, тики за 5 с | 0 | 0 |
| RssAnon в конце / максимум проб каждые 50 мс, КиБ | 36144 | 35860 |
| Сцена+GL, средние интервалы после старта, мс | 0,80–0,96 | 0,85–0,93 |
| Пик сцена+GL после старта, мс | 9,17 | 7,18 |
| CPU первого открытия меню, мс | 4,41 | 3,45 |

Прогоны не показывают регрессии простоя/памяти от второго соединения. Пики GL >1 мс
и стартовая растеризация CPU >4 мс есть в обеих сборках; это не полная приёмка
бюджетов SPEC или аппаратной DRM-сессии. В прогоне со снимком RssAnon кратковременно
достиг 78000 КиБ, затем вернулся к 37748 КиБ; он измерялся отдельно.
Исходные логи/JSON: `/tmp/feather-tray-before-20261026-idle`,
`/tmp/feather-tray-fix-20261026-idle`, `/tmp/feather-tray-fix-20261026-visual`.
Рабочая сессия пользователя не перезапускалась.

## Проверка

```sh
c++ -fPIC bench/tray.cpp -o /tmp/feather-tray-fixture $(pkg-config --cflags --libs Qt6Widgets Qt6DBus)
python3 bench/session-check.py tray --output /tmp/feather-tray
python3 bench/session-check.py tray --no-screenshot --output /tmp/feather-tray-idle
dbus-run-session -- cargo test --workspace -- --include-ignored
```

Runner сам создаёт **отдельную D-Bus шину**. Не включать FEATHER_DEBUG_TRAY и тестовые
действия на общей шине: там могут быть настоящие приложения пользователя. Ввод теста
поступает непосредственно в свой композитор; окно хоста выбирается только по PID.
Проверяются два QSystemTrayIcon Qt/KDE, меню и реальное действие, исчезновение/возврат
значка, снимок, живой PID и простой. Модульные тесты проверяют чужой watcher, регистрацию
нескольких соединений, пиксели, Passive/Active, поколения, disabled/submenu и выход владельца.
Отчёт по всей серии — [SESSION_CHECKS.md](SESSION_CHECKS.md).

## Ограничения

Поддерживается распространённый KDE/AppIndicator SNI + com.canonical.dbusmenu.
Legacy XEmbed/X11, OverlayIcon и анимированные AttentionMovieName пока не реализованы.
Если клиент не экспортирует DBusMenu, вызывается его ContextMenu; внешний вид такого
меню определяет клиент. Совместимость всех GTK/Electron клиентов и настоящая DRM
сессия ещё требуют отдельной приёмки, Qt-проверка их не заменяет.
