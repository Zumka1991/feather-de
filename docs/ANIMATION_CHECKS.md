# Анимации: реализация и проверка, 2026-10-23

Реализован функциональный объём задания 1 из HANDOFF. **Полная приёмка по бюджетам SPEC
остаётся открытой**: среднее время кадра укладывается, отдельные пики и приватная память — нет.
Это исходный отчёт по заданию 1. Позднее пользователь разрешил переход к заданию 2;
реализация глобального меню описана в [APPMENU.md](APPMENU.md).
Затем фоновые ассеты и плитки Launchpad вынесены в worker, подготовка соседних страниц
удалена. Новый отчёт: [RASTER_CHECKS.md](RASTER_CHECKS.md); числа ниже относятся к исходной
реализации анимаций до этой оптимизации.

## Поведение

- `animation.rs`: аналитическое решение критически затухающей пружины. Скорость сохраняется
  при развороте; нет фиксированной длительности и отдельного кадрового таймера.
- Состояние принадлежит `FeatherCompositor`. Активная пружина запрашивает следующий кадр;
  темп задают существующие события показа winit / DRM vblank. В конце значение и скорость
  фиксируются точно, `needs_redraw` снимается.
- Новое mapped-окно появляется с масштабом 0,92 → 1 и alpha 0 → 1. Поверхности, попапы,
  встроенное содержимое, декорация и 9-slice тень используют общий центр трансформации.
- Сворачивание сжимает окно к его слоту `DockTarget::Minimized`; восстановление использует
  сохранённое назначение. Фокус и hit testing исключают свёрнутое окно сразу, отрисовка
  продолжается до завершения полёта. Удалённые/unmapped окна убираются из состояния анимаций.
- Меню, Spotlight, Control Center и Launchpad появляются через alpha и масштаб 0,96 → 1.
  Изменение запроса поиска/выделения не перезапускает пружину. Закрытие панелей мгновенное;
  анимации уничтожения окна и увеличения Dock не входят в этот объём HANDOFF.
- GPU-трансформации используют прежние буферы; анимация не ставит CPU dirty-флаги.
  Кэш оверлея ограничен объединением видимых панелей, включая поля: координаты рисования
  локальные, фон стекла сохраняет привязку к экрану. Подготовка соседних страниц Launchpad
  начинается после остановки пружин.
- Скругляющий шейдер учитывает масштаб; у растягиваемых сегментов тени явно задан `src`.

## Проверки

`cargo build --release` — без предупреждений. `cargo test` — 4 теста:
одинаковое положение пружины при 60/144 Гц, сохранение скорости при развороте,
жизненный цикл окна/исключение свёрнутого окна из ввода, появление и очистка состояния панелей.

Вложенный режим под Hyprland, экран хоста 60 Гц, масштаб Feather ×2. Финальный прогон
без скриншота и без дополнительных настроек аллокатора: viewport 1864×1948 физических
пикселей. Это **не** подтверждение бюджета для DRM/4K.

| Метрика | Результат |
|---|---|
| Частота отдельных переходов | примерно 60 Гц (61–63 кадра/с по коротким сериям профайлера; стартовая серия 58) |
| Сцена+GL, среднее по переходу после старта | 0,44–0,82 мс |
| Сцена+GL, максимумы после стартовой серии | 0,84–2,44 мс; стартовая серия 8,72 мс |
| CPU подготовки на следующих кадрах стабильного перехода | 0,003–0,026 мс; буферы не растеризуются повторно из-за пружины |
| CPU на первом кадре открытия | меню/панели 9,9–17,4 мс; Launchpad 131,5 мс — тяжёлая подготовка остаётся |
| Swap, среднее | 0,05–0,10 мс |
| Простой после сценария | 0 тиков utime+stime за 5 секунд |
| RssAnon после Launchpad | 67,4–70,7 МиБ в повторных прогонах; в последнем 72376 КиБ |

Для сравнения отдельно собрана исходная версия `46ee758` с тем же отладочным сценарием
(без анимаций): после него RssAnon 71188 КиБ (~69,5 МиБ). Превышение памяти воспроизводится
и там. Эксперимент с порогами glibc не дал устойчивого выполнения бюджета; настройки
аллокатора в продукт **не добавлены**.

Снимки собственного framebuffer проверены для Qt/Konsole во время полёта к Dock, меню,
Control Center и Launchpad. Известное перекрытие Control Center уведомлением осталось
(задание 3). На момент этого прогона после debug-снимка воспроизводился
`ContextLost(EGLCreateSurface)`; позднее исправлен при задании 2 восстановлением поверхности
вывода. Замеры производительности выше сделаны отдельным запуском без снимков.

## Воспроизведение

```sh
XDG_CONFIG_HOME=/tmp/feather-animation-config FEATHER_PROFILE=1 \
  FEATHER_DEBUG_ANIMATIONS=1 FEATHER_SCALE=2 \
  timeout 18 target/release/feather-de --windowed
```

Сценарий: через 1 с свернуть активное окно, 2 с восстановить, 3 с меню приложения,
4 с Control Center, 5 с Spotlight, 6 с Launchpad, 7 с закрыть Launchpad. Это однократные
отладочные события, а не таймеры анимации. Строка профайлера «пружины остановлены» содержит
отдельную статистику завершившегося перехода.

Снимок промежуточного состояния (после снимка результаты профилирования не использовать):

```sh
XDG_CONFIG_HOME=/tmp/feather-animation-config FEATHER_DEBUG_ANIMATIONS=1 \
  FEATHER_DEBUG_SCREENSHOT=/tmp/feather-minimize.png FEATHER_DEBUG_SCREENSHOT_MS=1120 \
  timeout 5 target/release/feather-de --windowed \
  --autostart 'QT_QPA_PLATFORM=wayland konsole --separate --nofork -e sh -c "sleep 4"'
```

Останавливать только PID своего процесса/его `timeout`; ввод в окна хоста для этих проверок
не нужен. Невидимое окно вложенного композитора может не получить кадры хоста.

## Что осталось для приёмки задания 1

1. Снизить RssAnon после полного сценария до ≤60 МБ, включая кэши и удержание памяти
   аллокатором/драйвером; нельзя считать только исходный чистый рабочий стол.
2. Устранить пики сцены+GL >1 мс и тяжёлую подготовку первого кадра панелей/Launchpad.
   Связанная работа по фоновой растеризации уже стоит в задании 3 HANDOFF.
3. Проверка пользователем в DRM-сессии на целевом экране: частота, задержка ввода,
   бюджет кадра и памяти. DRM здесь не запускался.
