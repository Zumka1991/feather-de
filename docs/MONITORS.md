# Несколько мониторов — 2026-10-24

Реализована работа с несколькими выходами **одной основной видеокарты**. Настоящего
второго монитора для проверки нет: аппаратная приёмка DRM остаётся открытой.

## Поведение

- DRM перечисляет подключённые разъёмы, подбирает непересекающиеся CRTC и создаёт
  отдельный `DrmOutput` с собственной историей damage и буферами на каждый выход.
  Подбор учитывает ограниченные наборы CRTC, а не отдаёт первый доступный всем подряд.
- Udev сообщает об изменениях; постоянного опроса мониторов нет. Отключённые выходы
  удаляются из Wayland registry, окна и сохранённые положения восстановления остаются
  доступными на оставшемся экране. Возврат из VT повторно проверяет подключения.
- «Системные настройки → Дисплеи»: основной экран и расположение остальных слева,
  справа, сверху или снизу. Перекрывающее размещение отклоняется. Схема сохраняется
  через существующий worker настроек и восстанавливается при следующем входе.
- Основной экран имеет логическое начало `(0, 0)`; слева и сверху разрешены
  отрицательные координаты. Меню-бар, Dock и значки рабочего стола — на основном.
  Новые окна открываются на экране под указателем. Разворачивание, полноэкранный режим
  и ограничения всплывающих меню используют экран окна, включая запрошенный клиентом
  `wl_output` для fullscreen. Поверхности получают `wl_surface.enter/leave`.
- При смене схемы отменяются незавершённые захваты ввода и перетаскивания; окно,
  развёрнутое на отключённом экране, переносится и подгоняется под оставшийся.
- Обои используют общую GPU-текстуру. Общего CPU-буфера размером со все мониторы нет.
  Каждый выход получает сдвинутую сцену и собственное отсечение по границам экрана.
- Экран блокировки скрывает рабочий стол **на всех выходах**. Родной пароль показывается
  на основном, остальные экраны чёрные. Внешний `ext-session-lock` может создать
  отдельную поверхность для каждого монитора; ввод переводится в её локальные координаты.
  Подтверждение защищённого DRM-кадра ждёт все выходы. Завершение клиента оставляет
  сессию заблокированной. DPMS, смена VT и ночная гамма обрабатывают все CRTC.

## Границы этого этапа

Масштаб интерфейса пока общий. Разрешение/частота в настройках меняются у основного
экрана; другой экран можно сначала сделать основным. Отдельные масштабы, вращение,
зеркалирование, несколько GPU, VRR/explicit sync/direct scanout не входят в этот этап.
Поддерживается до восьми подключённых выходов. Отправка кадров использует общий барьер
ожидания всех поставленных в очередь выходов; независимое ускорение более быстрого
монитора при разных частотах — дальнейшая оптимизация.

Вложенная проверка показывает виртуальные выходы последовательно в одном тестовом
окне. Она проверяет общую модель, сцену и настоящие протокольные события, но не
заменяет проверку физических KMS page flip, пропускной способности, hotplug и VT.
Рабочая DRM-сессия пользователя не перезапускалась, аппаратные режимы не менялись.
Общая приёмка старых пиков сцены/GL и CPU-панелей по SPEC остаётся открытой.

## Воспроизведение

```sh
ss -xlp | rg 'wayland-'
python3 bench/monitor-check.py --host wayland-1 --scale 2 --output /tmp/feather-monitors-budget
python3 bench/monitor-check.py --host wayland-1 --scale 2 --screenshot --output /tmp/feather-monitors-visual
```

Скрипт создаёт собственный вложенный композитор, отдельную D-Bus-сессию, конфигурацию
и данные. Реальные звуковая/системная службы отключены в fixture. Ввод только через
обработчики своего процесса (`FEATHER_DEBUG_INPUT_ONLY=1`), окно прозрачно для ввода
хоста. Завершается только собственная группа процессов, в том числе после ошибки.

Сценарии: настоящее окно Терминала (CSD) и Super+перетаскивание, максимизация,
fullscreen, отрицательные координаты, смена основного, отключение развёрнутого окна,
возврат выхода, блокировка при отключении/подключении. Отдельный Wayland-клиент
проверяет registry/координаты; клиент блокировки — две поверхности, локальный ввод
второго экрана и завершение владельца. Третий запуск проверяет сохранённую схему.
Из снимков проверяются собственные кадры, включая полностью чёрные закрытые выходы.
Окно CPU-замера — не менее 5 с после окончания сценария и стартового приветствия.

## Итоговая проверка

`cargo build --release` — без предупреждений.
`dbus-run-session -- cargo test --release --workspace -- --include-ignored` —
**172 теста прошли**. Новые проверки: выбор CRTC без конфликтов, проекция указателя
на реальные экраны, отрицательные координаты/смена основного, сохранение схемы,
восстановление окна с отрицательного экрана. Страница «Дисплеи» дополнительно
отрисована с двумя экранами в светлой/тёмной теме при ×1/1,25/2 и просмотрена:
`/tmp/feather-monitors-settings-fixtures/Displays-2-false.png`.

Мгновенный `settings.png` попадает в начало анимации открытия; для оценки вёрстки
использованы фикстуры страницы, а не этот кадр.

Внешние поверхности проверены также визуально:
`/tmp/feather-monitors-external-first/external` — второй выход имеет заданный клиентом
цвет, после гибели владельца полностью чёрный. Там 0 тиков/5,035 с.
Пики сцены/GL и CPU-панелей выше SPEC сохраняются (особенно с readback); общая
