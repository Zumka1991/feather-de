# Wine, Proton и игры (2026-10-26)

## Масштаб

Настройки → Дисплеи → «Увеличивать Wine и старые приложения» (по умолчанию включено).
Весь собственный XWayland-дисплей получает preferred fractional scale = 1; при масштабе
рабочего стола ×2 пиксель X11 становится двумя экранными пикселями. Это GPU-масштабирование
готового окна, поэтому картинка может быть мягче нативного HiDPI. Нативные Wayland-клиенты
сохраняют масштаб рабочего стола. Реестры Wine и настройки Heroic не меняются.

Флаг `xwayland_hidpi` сохраняется в settings.conf. Для чёткого X11 HiDPI с DPI самого
приложения его можно выключить. Настройка относится ко всему собственному satellite:
он публикует общие XSETTINGS, поэтому смешивать разные preferred_scale для его окон нельзя.
Клиент определяется по PID запущенного нами satellite и учётным данным Wayland-сокета,
а не по произвольному имени окна. После переключения отправляется configure: satellite
должен закоммитить новый viewport даже у статичного X11-клиента.

Поведение satellite проверялось по исходникам тега
[v0.8.3](https://github.com/Supreeeme/xwayland-satellite/tree/v0.8.3), в частности
`src/server/event.rs` и `src/server/mod.rs`. Ограничения Wine/DPI описаны в его
[README](https://github.com/Supreeeme/xwayland-satellite/blob/v0.8.3/README.md).

## Указатель

`src/pointer_constraints.rs` подключает `zwp_relative_pointer_manager_v1` и
`zwp_pointer_constraints_v1`. DRM/libinput передаёт ускоренные и исходные относительные
дельты с микросекундным временем. Когда захват не заблокирован, `relative_motion` и
абсолютный `wl_pointer.motion` отправляются в одном `wl_pointer.frame`, чтобы `Xwayland`
видел `has_relative == true` и выставлял `POINTER_NORAW` (без синтеза ложного `XI_RawMotion`
из разницы абсолютных координат). В lock абсолютные движения не отправляются, курсор
скрыт; для нативных Wayland-клиентов hint применяется после снятия lock, а для XWayland
обновляет `pointer_location` без эхо-отправки голого `wl_pointer.motion`. При warp с
зажатой кнопкой мыши на XWayland (например, вращение камеры ПКМ в Lineage II / Wine, где
`SetCursorPos` + `ClipCursor` на `InputOnly`-окне `clip_window` закрывает 5‑мс
`pointer_warp_emulator` без создания `ConfinedPointer`) относительный захват (`x11_warp_lock`)
и исходная точка `SavedCursor` удерживаются до отпускания кнопки мыши.
Confinement учитывает размер surface, input region, отверстия и раздельные прямоугольники:
движение не проходит через запрещённую область. Число прямоугольников ограничено 128.
Данные surface и ограничения читаются последовательно, без вложенного захвата SurfaceData.

Захват разрешён только поверхности с клавиатурным фокусом. Alt+Tab, оболочка, блокировка
и потеря ввода снимают захват и отпускают удержанные клиентом кнопки; физический release
после переключения поглощается. На время открытого `Alt+Tab` фокус клавиатуры снимается
(`target = None`), а при любом перехваченном `KeyState::Released` и перед каждой сменой
фокуса в `refresh_focus()` очищается внутренний список `forwarded_pressed_keys` Smithay и
синхронизируется `wl_keyboard.modifiers` — чтобы при возврате в окно игры по `Alt+Tab` или
кликом мыши `wl_keyboard.enter` никогда не передавал залипший `Alt_L` (`Keycode(64)`) в
`xwayland-satellite` / `Xwayland` и клавиатура работала сразу без смены раскладки.
Обычное уведомление игру не разблокирует. В простое нет
нового таймера, потока или опроса. `refresh_focus()` остаётся единственным местом смены
клавиатурного фокуса.

Вложенный Winit передаёт абсолютные движения хоста, но не raw DeviceEvent::MouseMotion.
Поэтому протоколы проверяются синтетическими дельтами внутри собственного тестового
композитора; интерактивную игровую камеру нужно принимать в настоящей DRM-сессии.

## Dock и размер окна

xdg title/app_id теперь обновляют метаданные сразу по запросу, без ожидания нового
буфера. Proton/UMU `steam_app_default` не объединяет разные игры в один значок.
Безымянное служебное окно с тем же placeholder исключается из Dock/Alt+Tab/автофокуса,
когда есть именованное игровое окно. Клик по значку окна выбирает уже существующее окно.
Сообщённый пользователем повторный запуск процесса отдельно не воспроизведён: исправлены
подтверждённые ошибки идентификации окна и выбора служебного окна.

Раньше внешняя полоса resize существовала только при SSD Пёрышка. Теперь она доступна
также собственным XWayland-окнам с CSD (кроме fullscreen/maximized). При перекрытии окон
внешняя полоса верхнего окна имеет приоритет над поверхностью нижнего окна. Заголовок
поверх рамки Wine не добавляется. Начало/конец resize сообщает xdg state `Resizing`; реальный
размер берётся из следующего буфера клиента. Приложение всё ещё может ограничить размер
или иметь фиксированное внутреннее разрешение игры.

## Проверки

Изолированные клиенты, отдельная D-Bus шина, ввод только внутри своего вложенного
композитора; пользовательская игра не получает тестовых кликов и не перезапускается.

```sh
cargo build --release
dbus-run-session -- cargo test -p feather-de -- --include-ignored --test-threads=1
python3 bench/game-check.py --mode pointer --output /tmp/feather-pointer-check
python3 bench/game-check.py --mode x11 --output /tmp/feather-x11-check
```

`bench/game-pointer.c` проверяет lock/unlock, точные относительные дельты и время,
отсутствие абсолютных движений при lock, hint после unlock, смену фокуса, confinement
и потерю ввода. Метаданные меняются без commit до запроса lock.
`bench/game-x11.c` создаёт два именованных окна Proton и безымянное служебное.
Проверяются геометрия при переключении HiDPI, координаты нажатий X11, состав Dock/Alt+Tab,
выбор уже открытого окна и настоящий X11 ConfigureNotify после растягивания края.

Финальная release-сборка без предупреждений; 141 тест композитора прошёл.
Оба сценария на release прошли: pointer — 0 тиков/5 с, максимум секундных сэмплов
RssAnon 36280 КиБ (35,43 МиБ); X11 — 0 тиков/5 с, 34316 КиБ (33,51 МиБ).
Профиль после старта: pointer сцена+GL 0,57–1,34 мс, X11 1,05 мс;
худшие кадры 5–38 мс, первые CPU-кадры оболочки превышают 4 мс.
Как и прежние вложенные замеры на активном хосте, это не закрывает бюджет ≤1 мс:
общая DRM-приёмка производительности остаётся открыта. Новые таймеры не добавлены.
Настройки проверены своим снимком и полным сценарием: 0 тиков/5 с, RssAnon после
readback 57100 КиБ, пик снимка 97604 КиБ (в отдельном бюджете снимка).
Приёмка Lineage II (камера/ПКМ, UI, resize, значок Dock) в DRM остаётся за пользователем
после повторного входа в сессию с новым бинарником.
