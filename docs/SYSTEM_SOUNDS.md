# Системные звуки — 2026-10-25

В «Системных настройках → Звук» добавлена группа «Сигналы и звуки интерфейса»:

- предупреждения: включение, три собственных сигнала («Пёрышко», «Стекло», «Капля»)
  и отдельное прослушивание;
- громкость предупреждений и интерфейса: 0 / 25 / 50 / 75 / 100 % относительно
  текущего уровня устройства; ноль полностью отключает эти сигналы;
- звук после успешного снимка экрана (по умолчанию включён);
- отклик подтверждённого изменения громкости медиаклавишами (по умолчанию выключен);
  при mute, нулевом уровне или ошибке службы сигнала нет;
- прежний независимый переключатель звука уведомлений доступен и здесь.

Все настройки сохраняются в `settings.conf`: `alert_sounds`, `alert_sound`,
`alert_volume`, `interface_sounds`, `volume_feedback`. Старые конфигурации получают
предупреждения/интерфейс с уровнем 50 %, отклик клавиш выключен. Повреждённые значения
отбрасываются. Эти параметры не меняют громкость выхода или микрофона.

`xdg_system_bell_v1` и `gtk_shell1.system_bell` дают приложениям системный сигнал.
«Терминал» передаёт BEL активной вкладки через необязательный `xdg_system_bell_v1`;
на других композиторах без протокола продолжает работать. Ошибка немедленного
действия в системных настройках также подаёт сигнал предупреждения.

«Не беспокоить» отключает автоматические звуки. Выбор сигнала, его громкости и
«Прослушать» являются явным предпрослушиванием и работают при выключенных
предупреждениях/«Не беспокоить». Во время блокировки и при громкости сигналов 0
предпрослушивание тоже запрещено. Уведомления сохраняют свою политику и независимую
громкость: файл/тема играет с прежним уровнем; если темы нет, используется встроенный
сигнал. `suppress-sound`, обновление баннера, «Только центр» и выключенный
`notify_sounds` по-прежнему не дают звук.

## Выполнение

Один общий worker `feather-sound` обслуживает системные звуки и уведомления.
Главный поток выполняет проверку нескольких флагов и `try_send`; резервирование
через AtomicBool исключает очередь даже для серии событий в одном обороте цикла.
Пока проигрыватель занят, следующие сигналы отбрасываются. Нет накопления процессов,
воспроизведение уведомлений больше не зависит от очереди D-Bus-сигналов закрытия.

Worker спит на `recv`. Только при звуке он находит исполняемый `pw-play`, `paplay`
или `canberra-gtk-play`, синтезирует PCM WAV (48 кГц, mono, ≤ 0,32 с / 31 КиБ),
записывает в анонимный `memfd` и запускает проигрыватель без shell. Файл доступен
проигрывателю через `/proc/<pid>/fd/<fd>`; после завершения fd закрывается, кэша
на диске нет. Громкость встроенных сигналов задаётся амплитудой PCM. Аудиозаписи,
периодического опроса и таймера перерисовки нет. Ожидание процесса ограничено 4 с,
после чего worker завершает и собирает свой процесс; ошибка видна в логе и на
открытой странице звука.

## Проверки

`cargo build --release` и `dbus-run-session -- cargo test --release --workspace -- --include-ignored`.
Тесты проверяют границы/огибающие/амплитуду WAV, политику тишины, сохранение и
валидацию параметров, единственный процесс при всплеске, чтение реального memfd,
ошибку и восстановление проигрывателя, завершение зависшего процесса.

Воспроизводимый вложенный сценарий (сначала проверить владельца host-сокета):

```sh
python3 bench/audio-key-check.py --host wayland-1 --system-sounds --scale 2 \
  --protocol-summary --output /tmp/feather-system-sounds
python3 bench/audio-key-check.py --host wayland-1 --system-sounds --restore-sounds \
  --scale 2 --protocol-summary --output /tmp/feather-system-sounds
python3 bench/audio-key-check.py --host wayland-1 --system-sounds --scale 2 \
  --screenshot --protocol-summary --output /tmp/feather-system-sounds-visual
```

Используются отдельные D-Bus/конфигурация, подставные `pactl` и `pw-play`.
Проигрыватель только читает готовые WAV и записывает число сэмплов/пиковую
амплитуду; рабочая звуковая служба не меняется, слышимого звука нет. Клики идут
через обработчики собственного окна с пустой областью ввода хоста. Уведомление
от настоящего `notify-send` и BEL настоящего Терминала проходят Wayland/D-Bus.
Повторный запуск проверяет настройки и отсутствие звука при восстановлении.

## Итог проверки

Release без предупреждений; **184 теста workspace прошли**. Вложенные прогоны
выполнялись внутри работающего Пёрышка, а не на прежнем хосте Hyprland:
это функциональная проверка вложенного режима, не аппаратная приёмка DRM.

| Восстановление, без воспроизведения | 40,39 МиБ | 40,39 МиБ | 0 / 5,003 с | 0 |
| Звуки со снимком | 92,97 МиБ | 53,42 МиБ | 0 / 5,049 с | 0 |

Пик снимка 2880×1800 укладывается в добавочные два RGBA-кадра, память
вернулась ниже 60 МБ за 0,208 с. Настройки звуков не выполнили ни одной команды
изменения аппаратной громкости. Снимок новой страницы и фикстуры светлой/тёмной темы (×1/1,25/2) проверены;
дополнительно просмотрена прокрутка к устройствам при ×1,25.
Регрессия микрофона: 11 команд прошли, пик 47,03 МиБ, 0 тиков/5,042 с,
0 событий ввода хоста (`/tmp/feather-system-sounds-microphone-final/report.json`).
Предыдущий регрессионный прогон с одним событием ввода хоста не использован
для приёмки простоя, хотя функциональные проверки и 0 тиков прошли.
Отчёты: `/tmp/feather-system-sounds/scenario-report.json`, `report.json` (восстановление),
`/tmp/feather-system-sounds-visual/report.json` и `frame.png`.

Прежние превышения общих CPU/GL-бюджетов не закрыты: в визуальном вложенном
прогоне худший профилированный кадр 290,06 мс (со снимком), при восстановлении
29,17 мс. Работа системных настроек на raster worker также превышает 4 мс.
Эти замеры на активной рабочей сессии не являются приёмкой производительности DRM.

Слышимый звук через настоящий проигрыватель, устройства и их mute нужно проверить
в DRM после следующего входа: «Звук → Прослушать сигнал», три сигнала/громкость,
снимок экрана, отклик медиаклавиш, BEL (`printf '\a'` в Терминале),
«Не беспокоить» и выключатели. Рабочая DRM-сессия не перезапускалась.
